# Caddyfile smoke test

[`caddy-smoke.sh`](caddy-smoke.sh) runs the real [`deploy/caddy/Caddyfile`](../Caddyfile) under the Velexis Caddy build (Caddy 2.8.4 with the Coraza web application firewall, task X-039) on the loopback interface, with [`echo-upstream.mjs`](echo-upstream.mjs) in place of the apps, and checks with `curl` what a browser, an SDK user and an attacker would see. Task [X-022](../../../docs/mvp/plans/foundation-tasks.md) created it. CI runs it in the `deploy-files` job of [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml), so every Caddyfile change is tested end to end before it reaches the VM.

Read first: [ADR-0018](../../../docs/mvp/adr/0018-hosted-storefront-custom-domains.md) (storefront, edge headers, `ask`), [`deployment-single-vm.md`](../../../docs/mvp/deployment-single-vm.md) §6 (Caddy and TLS, the web application firewall), [ADR-0027](../../../docs/mvp/adr/0027-pci-scope-and-vm-controls.md) rows 1.4, 4 and 6.4.2 (admin socket, TLS and HSTS, the WAF).

## Run it

It needs no root and no network beyond `127.0.0.1`: the Velexis Caddy build, Node 22, `curl`, `openssl`, `awk` and `sha256sum`. The app ports 3000, 3001, 3002, 3100 and 4000 (echo upstream), 8080 and 8443 (Caddy) must be free, and nothing may listen on 2019. A run takes about 15 seconds.

```bash
# The Velexis Caddy build (Linux x86_64, outbound HTTPS to proxy.golang.org and sum.golang.org, about 2 minutes;
# it fails unless the binary's SHA-256 is the CADDY_SHA256 of deploy/caddy/build/versions.env)
bash deploy/caddy/build/build-caddy.sh /tmp/caddy-build

bash deploy/caddy/test/caddy-smoke.sh                       # uses /tmp/caddy-build/caddy
CADDY=/path/to/caddy bash deploy/caddy/test/caddy-smoke.sh  # another copy of the same build
```

It prints one `PASS` or `FAIL` line per check and ends with `caddy-smoke: all checks passed` (exit 0) or `caddy-smoke: FAILED` (exit 1). Check names end with the acceptance criterion or lead decision they prove (`[X-022 AC1]`, `[X-039 AC2]`, `[X-029 AC1]`, `[FIX-W51-SHARED 20q]`). On a failure it prints the last lines of Caddy's and the echo upstream's logs.

| Setting | Default | Meaning |
|---|---|---|
| `CADDY` | `/tmp/caddy-build/caddy` when it exists, else `caddy` on `PATH` | The Caddy binary. It must be v2.8.4 with the module `http.handlers.waf` (anything else is refused), and the check that it is the pinned build (`CADDY_SHA256`) fails for any other binary. |
| `SMOKE_NODE` | `node` on `PATH` | Node for the echo upstream and for reading JSON |
| `SMOKE_TMPDIR` | `TMPDIR`, else `/tmp` | Parent of the temporary folder. The admin socket lives in it, and a unix socket path must stay under 100 bytes. |
| `SMOKE_KEEP=1` | off | Keep the temporary folder: the test copy, `caddy.log`, `echo.log`, Caddy's data folder with its local CA |

## How it works

1. **Production file.** `caddy validate` and `caddy fmt --diff` must be clean. `caddy adapt` with an empty environment must show only the placeholder hosts of [`decisions.md`](../../../docs/mvp/decisions.md) §4, the admin address `unix//run/caddy/admin.sock` and the file roots `/srv/velexis/maintenance` and `/srv/velexis/current/storefront` (so `VELEXIS_ROOT` has no default). The caddy unit's drop-in [`velexis.conf`](../../systemd/caddy.service.d/velexis.conf) is read as systemd reads it (step 1b): after the package's `caddy run --environ`, its empty `ExecStart=` leaves only its own command, which has no `--environ`; where `systemd-analyze` is installed, it loads the drop-in on top of the package's unit without a complaint and refuses the same drop-in without the empty `ExecStart=`.
2. **Test copy.** Only the global options block changes (the log snippets before it, which its log imports, stay as they are): the admin socket moves to `<tmp>/admin.sock`, and `local_certs`, `skip_install_trust`, `default_bind 127.0.0.1`, `http_port 8080` and `https_port 8443` are added. The rest of the block stays, including the production `ask` URL `http://127.0.0.1:3100/internal/tls/ask`, which reaches the echo upstream. Every snippet and site block is the production text byte for byte; the script checks that.
3. **Environment.** Caddy runs with `env -i` and only `PLATFORM_BASE_DOMAIN=platform.localhost`, `STOREFRONT_BASE_DOMAIN=ota.localhost`, a random `VELEXIS_EDGE_SECRET`, `VELEXIS_ROOT=<tmp>/root`, `VELEXIS_WAF_DIR=<tmp>/root/etc/caddy/waf` (a copy of [`deploy/caddy/waf`](../waf), the firewall's rule files, as `velexis-deploy` installs them in `/etc/caddy/waf`), and `HOME` and the XDG folders inside the temporary folder (its local CA and certificates land there; nothing is installed in the system trust store). `VELEXIS_ROOT` is a prefix the Caddyfile puts in front of `/srv/velexis/…`; it is never set on the VM, where it expands to nothing. Under it the script builds a storefront release (`releases/smoke/storefront` with `index.html`, `404.html`, `p.html`, `assets/a.js`, `checkout.html` and `checkout/pay-airline.html`, `pay-card.html` and `complete.html`, and the symlink `current`) and copies [`maintenance/index.html`](../maintenance/index.html).
4. **Echo upstream.** `echo-upstream.mjs` listens on every app port the Caddyfile proxies to (3000, 3001, 3002, 3100 and 4000) and answers every request with a JSON echo of its port, method, URL, the number of request body bytes that arrived (`bytes`) and headers (each header as the list of values it received); `GET /redirect` answers 302 with `Location: /landing?<its own query>` and the same echo. Every answer carries `Cross-Origin-Opener-Policy: same-origin`, as helmet adds it to every answer of both APIs, and the OTA API's helmet CSP `default-src 'none'; frame-ancestors 'none'`. On 4000, `GET /v1/assets/<key>/<id>.<ext>` answers as `getPublicAsset` does: `image/png` with the image's own headers (`Content-Security-Policy: default-src 'none'`, `Cache-Control: public, max-age=31536000, immutable`, `nosniff`, `Cross-Origin-Resource-Policy: cross-origin`). On 3100 it is also the `ask` endpoint: 200 for `acme.ota.localhost`, 404 for anything else, and one `ask <host> <status>` line in its log. It never prints header values.
5. **Requests.** `curl --resolve <host>:8443:127.0.0.1 --cacert <Caddy's local root CA> --noproxy '*'`, so no DNS and no proxy are involved.

## What it found (fixed in X-022)

- **Storefront internal paths reached the OTA API.** `respond @api_internal 404` sorts after `handle` in Caddy's directive order, so `/api/internal/*` and `/api/health/ready` on a storefront host were proxied to the OTA API, with the edge secret. The storefront now has a `handle @api_private { respond 404 }` before `handle /api/*`, and blocks `/api/health/*` except `/api/health/live`, as the API hosts do ([ADR-0016](../../../docs/mvp/adr/0016-observability.md)).
- **Error responses lost their security headers.** A `header` block that deletes a header (`-Server`) is deferred, and Caddy does not apply deferred headers to responses written by `handle_errors`. The maintenance page, the JSON envelope and the storefront 404 page had no HSTS, no CSP and a `Server: Caddy` header. Each `handle_errors` block now imports its header snippet (`security_headers`, or the new `storefront_headers`).
- **Hard-coded `/srv/velexis` paths** made the file untestable without root. They now start with `{$VELEXIS_ROOT}`, which is empty on the VM.
