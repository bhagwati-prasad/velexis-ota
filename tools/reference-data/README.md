# `@velexis/reference-data`

The vendored reference datasets of the `reference` schema ([`reference.sql`](../../docs/velexis-sdk/db/reference.sql)): currencies, countries, time zones, cities, airports, airlines and aircraft, built from **OpenTravelData** (CC BY 4.0) and **Unicode CLDR** (Unicode License v3) as [ADR-0024](../../docs/mvp/adr/0024-reference-data-sources-and-loader.md) decides. The snapshots are committed and reviewed like code. CI, deploys and tests **never download** them.

- Task [X-017](../../docs/mvp/plans/foundation-tasks.md) built the fetch and validation scripts and the first snapshot (this folder).
- Task X-018 adds the TypeScript loader (`dist/cli/load.js`, `pnpm db:seed:reference`) that upserts `data/` into PostgreSQL. Until then the package has no build.

## Layout

| Path | What |
|---|---|
| `data/*.csv` | One file per table, in foreign-key order: `currencies`, `countries`, `time_zones`, `cities`, `airports`, `airlines`, `aircraft`. Generated by `scripts/fetch.mjs`; **never edit them by hand**. |
| `data/overrides.csv` | Manual fixes (`table,key,column,value`), empty by default. The only file in `data/` that people edit. |
| `SOURCES.md` | Generated with each snapshot: retrieval date, URL, licence, size and SHA-256 of every raw download, the attribution line, the SHA-256 of every generated file, the notes of the snapshot and the Unicode licence notice. |
| `scripts/fetch.mjs` | Downloads the sources and rebuilds `data/` and `SOURCES.md` (by hand only), or checks the committed snapshot offline (`--check`). |
| `scripts/validate.mjs` | The offline checks, also used by `fetch.mjs` before it writes anything and by `--check`. |
| `scripts/*.test.mjs` | Vitest tests: the checks on small hand-written data sets, the mapping on fixture sources with a fake `fetch`, and the committed snapshot. |

`package.json` ships `dist`, `data` and `SOURCES.md` in releases (`pnpm deploy`, [ADR-0023](../../docs/mvp/adr/0023-release-artefact-and-deploy-user.md)), so the Unicode notice travels with the data.

## Commands

Plain Node 22, no dependencies (Vitest and ESLint only for the tests and lint).

| Command | What it does |
|---|---|
| `node tools/reference-data/scripts/fetch.mjs --check` (`pnpm --filter @velexis/reference-data check`) | Validates the committed files **offline** and exits non-zero on any problem. Safe in CI. |
| `node tools/reference-data/scripts/validate.mjs [--data <dir>] [--no-min-rows]` | The data checks alone, on any folder. |
| `NODE_USE_ENV_PROXY=1 node tools/reference-data/scripts/fetch.mjs` (`pnpm --filter @velexis/reference-data fetch`) | Downloads the sources and rewrites `data/*.csv` and `SOURCES.md`. **By hand only**, never in CI. `NODE_USE_ENV_PROXY=1` makes Node's `fetch` use `HTTPS_PROXY` (Node ≥ 22.21); it is harmless without a proxy. |
| `pnpm --filter @velexis/reference-data test` / `lint` | Vitest and ESLint. |

`--check` fails when:

- a file breaks a rule of `validate.mjs` (below);
- a generated file's SHA-256 differs from the one in `SOURCES.md` (it was edited by hand);
- `SOURCES.md` or its attribution line is missing;
- `data/` reaches 3 MB (the first snapshot is about 1.8 MB).

## Refreshing the snapshot (quarterly, as a normal pull request)

1. Read the [CLDR release notes](https://cldr.unicode.org/index/downloads) and, if a newer release exists, bump `CLDR_TAG` in `scripts/fetch.mjs` (a [cldr-json](https://github.com/unicode-org/cldr-json) tag). OpenTravelData has no releases: the script reads the `master` branch and records the SHA-256 of what it got.
2. Run `NODE_USE_ENV_PROXY=1 node tools/reference-data/scripts/fetch.mjs` on Node 22. It:
   - stops if the OpenTravelData README no longer states CC BY 4.0 or the CLDR `LICENSE` is no longer the Unicode License v3 (the licences are re-checked on every snapshot, ADR-0024);
   - stops, writing nothing, if the new snapshot fails validation, including a table shorter than its plausible minimum (`MIN_ROWS`);
   - keeps `data/overrides.csv` as it is (an override whose key disappeared now fails validation: remove it or move the fix upstream).
3. Review the diff (`git diff --stat tools/reference-data`, the notes in `SOURCES.md`), run `pnpm --filter @velexis/reference-data test`, and open the pull request. The time zone offsets come from the ICU data of the Node version that ran the script; `SOURCES.md` records it.
4. After the merge, `velexis-deploy` reloads the data because the checksum of `data/` changed ([`deployment-single-vm.md`](../../docs/mvp/deployment-single-vm.md) §8).

To fix a single wrong value before the next refresh, add a line to `data/overrides.csv` instead (below). Report the error upstream to OpenTravelData or CLDR as well.

## File format

Every file is deterministic, so the same sources always give the same bytes:

- UTF-8 without a byte order mark, LF line endings, a final newline, no blank line;
- a header row with exactly the columns of the table in `reference.sql`, in DDL order, without `created_at` and `updated_at` (the loader sets them);
- comma-separated, quoted only when a value contains a comma, a quote or a line break (RFC 4180, `""` inside quotes);
- one row per key, sorted by key in plain code-unit order (digits before letters, `A` before `a`);
- an empty field is `NULL`; booleans are `true` / `false`; coordinates have at most 6 decimals (`numeric(9,6)`), integers have no decimals.

`validate.mjs` checks, for every file:

- the format above, the header, the number of fields;
- every value against its column: type and range, `NOT NULL`, and the `CHECK` constraints of `reference.sql` (code regexes, latitude −90..90, longitude −180..180, `minor_units` 0..4, and the `kind`, `alliance`, `body_type` and continent lists), plus no control characters, no surrounding spaces and Unicode NFC for text;
- unique, sorted keys, and the `UNIQUE` columns (`countries.alpha3`, `airports.icao_code`, `airlines.icao_code`);
- every foreign key inside the files (country → currency; time zone → country; city → country, time zone; airport → city, country, time zone; airline → country), after the overrides are applied;
- the plausible minimums: currencies 150, countries 240, time zones 300, cities 5,000, airports 8,000, airlines 700, aircraft 200.

A test compares these rules with `reference.sql`, so a change of the DDL that the files do not follow fails `pnpm test`.

## Mapping

| Table | Source | Rules |
|---|---|---|
| `currencies` | CLDR `currencies.json` (English names, symbols), `currencyData.json` (minor units), `codeMappings.json` (numeric codes) | Every ISO 4217 code with an English CLDR name, historic ones included. `minor_units` = CLDR `_digits` (default 2). `is_active` = legal tender in at least one region on the retrieval date, so historic currencies, funds codes (`USN`, `CLF`…) and `X`-codes (`XAU`, `XDR`, `XTS`, `XXX`) are inactive. `symbol` = the CLDR English symbol, which is the code itself when CLDR has none. |
| `countries` | CLDR `territories.json`, `codeMappings.json`, `currencyData.json`; OpenTravelData `optd_countries.csv` | The ISO 3166-1 codes that CLDR maps to an alpha-3 and a numeric code below 900 (the officially assigned ones, 249), plus the user-assigned codes that OpenTravelData's country list also has (`XK`, Kosovo, used by OpenTravelData's locations), without alpha-3 or numeric code. `name` = the CLDR English name. `currency_code` = the region's first current legal tender. `continent_code` and `calling_code` from `optd_countries.csv` (`tel_pfx`, country code only: `+1-268` → `1`). `is_eu` from the 27-code list `EU_MEMBERS` in `fetch.mjs`. `official_name` stays empty (no source). |
| `time_zones` | CLDR `bcp47/timezone.json` | Every IANA name of the non-deprecated keys, aliases included (`Asia/Calcutta` and `Asia/Kolkata`), so OpenTravelData's names always resolve; not `Etc/Unknown`. `country_code` = the key's `_region`, else the first two letters of a five-letter UN/LOCODE key (`frpar` → `FR`); none for `UTC`, `Etc/GMT+n`, and the few zones whose key has another length and no `_region` (`gldkshvn`, `America/Danmarkshavn`), as UTS #35 defines. Offsets with `Intl` at 12:00 UTC on 15 January and 15 July of the snapshot year: `utc_offset_minutes` = the smaller, `dst_offset_minutes` = the larger, `NULL` when they are equal. |
| `cities` | OpenTravelData `optd_por_public.csv` | The rows whose location type contains `C` (city), one per IATA code. `name` = the row's name for a pure city row, else the city's own entry in the served-cities list (a city + airport row is named after the airport). `state_code` only for US, CA, AU and BR (as the DDL comment says), from `iso31662` when it is a valid code there. `search_rank` = page rank × 1,000,000, rounded (0 when missing). |
| `airports` | OpenTravelData `optd_por_public.csv` | The rows with an IATA code whose location type contains `A` (airport), `H` (heliport), `R` (rail station) or `B` (bus station); ports, off-line points and pure cities are left out. `kind`: `airport`, `heliport`, `rail_station`, `bus_station`, and `seaplane_base` / `heliport` for airports with the GeoNames feature code `AIRS` / `AIRH`. One row per code: an open row (no `date_until` before the retrieval date) beats a closed one, then the higher page rank, then the newer `date_from`. `is_active = false` for closed locations. `city_code` = the first served city that is in `cities.csv`; `city_name` = that city's name. `elevation_ft` = OpenTravelData's metres ÷ 0.3048, rounded. `search_rank` as for cities. When two airports share an ICAO code (`UNIQUE`), the open, higher-ranked one keeps it. |
| `airlines` | OpenTravelData `optd_airlines.csv` | Carriers only (`air-`, `trn-` and `bus-` records: airlines, rail and bus operators) with a valid two-character IATA code; GDS, technical and alliance codes are left out. One row per code: open first, then the higher flight frequency, then the newer validity. `accounting_code` = `num_code` padded to three digits (`57` → `057`; `0` = unknown). `alliance` for `Member` and `Affiliate` statuses. `country_code` = the country of the airline's base airports and cities when they all lie in one country; empty when the bases span several countries (the source has no country of registration, and the first base is not always the home one). `is_active = false` for ended records. `common_name` and `logo_url` stay empty and `is_low_cost` is `false` (no source). A shared ICAO code stays with the open, busier airline. |
| `aircraft` | OpenTravelData `optd_aircraft.csv` | `name` = manufacturer + model (the model alone when it already names the manufacturer). `icao_code` without OpenTravelData's placeholders (`*`, `ZZZZ`, `0000`). `body_type`: `helicopter`, `turboprop` and `other` (piston, surface equipment) from the aircraft type; jets are `wide` or `regional` by family (lists in `fetch.mjs`) and `narrow` otherwise; a generic group code (`330`) without a type takes the type its members agree on; empty when the source does not say. |

Every text is trimmed, on one line and in Unicode NFC. `SOURCES.md` lists, per snapshot, the codes these rules left without a city, a time zone, an ICAO code, a country (airlines) or a body type.

## Overrides (`data/overrides.csv`)

For an urgent fix between two refreshes, add one line per changed value:

```csv
table,key,column,value
airports,XYZ,name,Example International Airport
airports,XYZ,is_active,false
```

- `table` is one of the seven tables, `key` is the row's primary key, which must exist in that table's file, and `column` is any column but the key. An empty `value` sets `NULL` (only for nullable columns).
- The value must pass the same column rules as the files, and foreign keys and `UNIQUE` columns are checked after the overrides are applied. A column of a row can be overridden only once.
- The loader (X-018) applies the overrides after the files, in the same transaction.

## Attribution and licences

CC BY 4.0 requires attribution: the storefront's legal page and the OTA admin's About page carry the line **"Contains data from OpenTravelData (CC BY 4.0)"** (ADR-0024; the OTA plan adds it). `SOURCES.md` carries the same line, the licence links and the full Unicode License v3 notice, and ships with the data.

## Differences from the plan, to confirm

- **Telephone codes.** Unicode CLDR stopped publishing `telephoneCodeData` in release 34 (2018), so `calling_code` comes from OpenTravelData's `optd_countries.csv` (CC BY 4.0, already a source of this package), as does `continent_code`. Countries without a code there (uninhabited territories, and Kosovo) stay empty.
- **Extra downloads.** Besides the three OpenTravelData files the plan names, the script downloads `optd_countries.csv` (above), the OpenTravelData `README.md` and the CLDR `LICENSE` (to re-check the licences).
- **Minor units.** CLDR's `_digits` are display digits. For a few currencies they differ from the ISO 4217 minor units (for example `HUF`, `IDR`, `COP`, `PKR`: 0 in CLDR, 2 in ISO 4217; `IQD`: 0 and 3).
