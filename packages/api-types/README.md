# `@velexis/api-types`

The API contract package of Velexis ([ADR-0006](../../docs/mvp/adr/0006-contract-first-openapi.md)). It holds the TypeScript types generated from the two OpenAPI documents, the operations index used by the parity tests, the queue message contracts, and the Redocly lint of the documents. The documents are the source of truth; this package never defines a request or response shape by hand.

Related: [`packages/README.md`](../README.md#velexisapi-types) (public API sketch), [`ota/backend/openapi/README.md`](../../ota/backend/openapi/README.md) (how to change the OTA document), [`AGENTS.md` §6](../../AGENTS.md#6-contract-first) (contract first), [`tech-stack.md`](../../docs/mvp/tech-stack.md) §2.

## What is generated, and from where

Generated files are committed, start with `// Generated by scripts/generate.mjs — do not edit`, and are deterministic. CI runs the generator again and fails on any diff. Nothing under `src/generated/` is edited by hand: change the document, then regenerate.

| Import | Source | Generator | Output |
|---|---|---|---|
| `@velexis/api-types` (OTA: `paths`, `components`, `operations`, `$defs`) | [`ota/backend/openapi/velexis-ota-booking-api.openapi.yaml`](../../ota/backend/openapi/velexis-ota-booking-api.openapi.yaml) | `openapi-typescript` 7 | `src/generated/ota.ts` |
| `@velexis/api-types/platform` | `platform/backend/openapi/velexis-platform-api.openapi.yaml` (created by the platform plan in M1) | `openapi-typescript` 7; an empty placeholder until the document exists | `src/generated/platform.ts` |
| `@velexis/api-types/operations` | both documents | `scripts/generate.mjs` (`yaml` 2): `operationId`, method, path, `x-sdk-method`, `x-scope`, tags, `x-internal` | `src/generated/operations.ts` |
| `@velexis/api-types/jobs` | hand-written in `src/jobs/` | none: types and JSON Schemas of the queue messages ([ADR-0009](../../docs/mvp/adr/0009-background-jobs-bullmq.md)) | — |

The SDK contract in [`docs/velexis-sdk/sdk/src/`](../../docs/velexis-sdk/sdk/src/) imports `@velexis/api-types` by that name, which is why the package is not called `@velexis/contracts`.

## Commands

| Command | Does |
|---|---|
| `pnpm contracts:lint` | From the repository root: Turborepo runs this package's `contracts:lint` script, which lints every document that exists (below). Cached by Turborepo; the cache key includes both `openapi/` folders, `redocly.yaml` and the script. |
| `pnpm --filter @velexis/api-types contracts:lint` | The same without Turborepo and its cache |
| `pnpm contracts:generate` | Regenerates the types and the operations index (X-008; does nothing before it) |
| `pnpm --filter @velexis/api-types test` | Unit tests (Vitest), including the tests of `contracts:lint` (below) |
| `pnpm --filter @velexis/api-types typecheck` / `lint` | `tsc --noEmit` / ESLint |

The JSON form of a document, when a tool needs one, is generated into a scratch location and never committed:

```bash
cd packages/api-types
REDOCLY_TELEMETRY=off REDOCLY_SUPPRESS_UPDATE_NOTICE=true \
  pnpm exec redocly bundle ota --config redocly.yaml --ext json -o /tmp/velexis-ota.json
```

## `contracts:lint`

`node scripts/contracts-lint.mjs [--config <redocly.yaml>]` is step 2 of the contract workflow ([ADR-0006](../../docs/mvp/adr/0006-contract-first-openapi.md), Workflow): run it after every change to a document, before `pnpm contracts:generate`.

1. It reads the `apis` of [`redocly.yaml`](redocly.yaml): `ota` and `platform`, with their document paths relative to that file.
2. Every document that exists is linted, in one Redocly CLI run, with the rules of `redocly.yaml` and the `stylish` output (one line per problem: `line:column severity rule message`).
3. The **platform** document does not exist until the platform plan creates it in M1 (PBE-005). Until then the script prints `contracts:lint: skipped "platform": … does not exist yet; the platform plan creates it in M1 (ADR-0006).` and goes on. Once the file exists it is linted with no change here. Any other missing document (the OTA one) fails the run.
4. It exits 1 on any lint **error**, on a `redocly.yaml` that Redocly rejects (`--lint-config error`, so a misspelt rule name fails instead of being ignored), and when a `.redocly.lint-ignore.yaml` sits next to the config. Warnings are printed and do not fail the run.
5. Redocly CLI 1.x would otherwise send usage telemetry and check the npm registry for a newer version. The script sets `REDOCLY_TELEMETRY=off` and `REDOCLY_SUPPRESS_UPDATE_NOTICE=true` for the Redocly process, and `redocly.yaml` also says `telemetry: off`, so a lint never calls the network.

`--config` lints another copy of the repository layout (`<root>/packages/api-types/redocly.yaml` with the documents at their repository paths); the tests use it to lint broken copies without touching the real documents.

### The rules

[`redocly.yaml`](redocly.yaml) extends Redocly's `recommended` ruleset and sets:

| Rule | Severity | Why |
|---|---|---|
| `operation-operationId-unique` | error | Route parity, the operations index and the SDK route table are keyed by `operationId` |
| `no-unused-components` | warn | The documents keep shared schemas that no operation references yet |

The vendor extensions (`x-sdk-method`, `x-scope`, `x-amadeus`, the table extensions, `x-error-codes`, `x-error-catalogue`, `x-tagGroups`, `x-examples` and the others listed in [`ota/backend/openapi/README.md`](../../ota/backend/openapi/README.md) §2, plus the planned `x-internal`, `x-edge-only`, `x-sensitive`, `x-milestone`, `x-permission` and `x-sdk-exclude`) are allowed: OpenAPI 3.1 permits `x-*` keys wherever they are used, and the `struct` rule of `recommended` accepts them. No rule may reject them.

The copied OTA document lints with **0 errors and 10 warnings**: nine `no-unused-components` (six `Amadeus*` schemas carried over from [`docs/amadeus-api/`](../../docs/amadeus-api/): the four error shapes, `AmadeusFlightFilters` and `AmadeusFlightOfferPricingIn`; plus `TravelerFieldErrorCode`, `ConsoleApiKeyScope` and `ConsoleBookingTimeoutDetails`) and one `no-server-example.com` (the `http://localhost:4000` server). Fix a warning in the document when a task touches that part anyway; never silence it.

A problem is fixed in the document. Tightening a rule is a normal change; relaxing one, skipping one (`--skip-rule`) or adding an ignore file needs an ADR first ([`AGENTS.md` §7](../../AGENTS.md#7-tests-are-never-weakened)).

### Tests

[`src/contracts-lint.test.ts`](src/contracts-lint.test.ts) runs the script as a child process:

- `[X-007 AC1]` the OTA document of the repository lints with zero errors, and no problem concerns an `x-*` extension;
- `[X-007 AC2]` without a platform document the lint passes and prints the skip notice;
- `[X-007 AC3]` a copy of the OTA document whose second operation repeats the first `operationId` fails with `operation-operationId-unique`;
- a platform document is linted once it exists, and its errors fail the run; a missing OTA document, an ignore file, a misspelt rule in the config, a config without APIs and an unknown option fail it too.

Apart from AC1, the documents live in a scratch copy of the repository layout with a verbatim copy of `redocly.yaml`, in the system temporary folder, removed after the run. The two tests on the full OTA document take about five seconds each.

AC1 reads the documents outside this package, so `turbo.json` gives this package's `test` task its own inputs (`@velexis/api-types#test`): the generic ones plus both `openapi/` folders. A changed document therefore reruns these tests in `pnpm test` (locally and in CI, which restores the Turborepo cache) instead of replaying a cached pass.
