# B1 — Storefront, customer identity, account and reference data

Developer guide for the `storefront`, `auth`, `account` and `reference` namespaces of `@velexis/ota-sdk`
(declarations: `sdk/src/identity.d.ts`, API tag group **Storefront & identity**).

These namespaces bootstrap a Next.js storefront, sign customers up and in, manage their account and saved
travellers, and power search-form autocomplete and airline logos. **None of them calls Amadeus**: storefront
settings, customers, sessions and saved travellers live in the OTA's own tenant schema (`tenant_<key>`); airports,
cities, airlines, countries and currencies come from the shared, read-only `reference` schema.

| Namespace | What it is for | Key | User token |
|---|---|---|---|
| `storefront` | Bootstrap config: branding, domains, locales, currencies, markets, features, payment public config, legal, consent, SEO; host → OTA resolution for multi-domain hosting | publishable or secret (`resolve`: hosting or secret) | none |
| `auth` | Sign-up, email verification, sign-in, rotating refresh, sign-out, password reset/change, current session | publishable or secret | customer token for `getSession`, `changePassword` (optional for `resendVerification`, `signOut`) |
| `account` | Profile, preferences, saved travellers, data export, account deletion | publishable or secret | customer token (always) |
| `reference` | Location autocomplete, airports, airlines, countries, currencies | publishable or secret | none |

## 1. Clients

Create three clients once: an anonymous server client, a per-request customer client that reads the session
cookies, and a browser client with the publishable key (for client components such as autocomplete).

```ts
// lib/velexis.ts — server only
import "server-only";
import { cookies, headers } from "next/headers";
import { createVelexisClient, type EndUserContext, type Schemas } from "@velexis/ota-sdk";

const base = { secretKey: process.env.VELEXIS_SECRET_KEY!, baseUrl: process.env.VELEXIS_API_URL };
export const velexis = createVelexisClient(base); // anonymous server calls (storefront, reference, auth forms)

/**
 * The visitor behind the current request. Server calls with the secret key come from your server's IP, so pass this
 * as `options.endUser` (or the client option `endUser`): the API then applies per-IP rate limits and sign-in lockouts
 * to the visitor, not to your server, and records the visitor's user agent / IP country on new sessions.
 * Trust `x-forwarded-for` only when your own hosting proxy sets it (Vercel, Cloudflare, your load balancer).
 */
export async function endUserFromHeaders(): Promise<EndUserContext> {
  const h = await headers();
  const ip = h.get("x-forwarded-for")?.split(",")[0]?.trim() || h.get("x-real-ip") || undefined;
  return { ip, userAgent: h.get("user-agent") ?? undefined };
}

export const AT = "vx_at";
export const RT = "vx_rt";
const cookie = { httpOnly: true, secure: true, sameSite: "lax" as const, path: "/" };

/** Store tokens in httpOnly cookies; the access-token cookie expires 60 s early so middleware refreshes in time. */
export async function setSessionCookies(s: Schemas["Session"]) {
  const jar = await cookies();
  jar.set(AT, s.accessToken, { ...cookie, expires: new Date(Date.parse(s.accessTokenExpiresAt) - 60_000) });
  jar.set(RT, s.refreshToken, { ...cookie, expires: new Date(s.refreshTokenExpiresAt) });
}
export async function clearSessionCookies() {
  const jar = await cookies();
  jar.delete(AT);
  jar.delete(RT);
}

/** Client acting as the signed-in customer (server components, server actions, route handlers). */
export async function customerClient() {
  const jar = await cookies();
  return createVelexisClient({
    ...base,
    locale: jar.get("vx_locale")?.value,
    currency: jar.get("vx_currency")?.value,
    accessToken: () => jar.get(AT)?.value,
    refreshToken: () => jar.get(RT)?.value,
    endUser: endUserFromHeaders, // X-Velexis-End-User-IP / -Agent on every call of this request
    // Cookies are writable only in server actions / route handlers; in server components middleware refreshes first.
    onSessionRefreshed: (s) => setSessionCookies(s).catch(() => undefined),
    onSessionExpired: () => clearSessionCookies().catch(() => undefined),
  });
}
```

```ts
// lib/velexis-browser.ts — client components (publishable key; origin must be allow-listed for the key)
import { createVelexisClient } from "@velexis/ota-sdk";
export const browserClient = createVelexisClient({ publishableKey: process.env.NEXT_PUBLIC_VELEXIS_PUBLISHABLE_KEY! });
```

Calls from the browser client need no `endUser`: they come from the visitor's own IP, and the API ignores the
end-user headers for publishable keys.

`@velexis/ota-sdk/next` ships ready-made equivalents of these helpers (server client from cookies, cookie
session helpers, refresh middleware); the code above shows exactly what they do.

> Never put the secret key or the refresh token into client components. `auth.signIn`, `auth.signUp`,
> `auth.refresh`, `auth.resetPassword` and `auth.changePassword` return tokens — call them from server actions or
> route handlers and write the tokens straight into httpOnly cookies.

## 2. Flow: bootstrap the storefront (`storefront.get`)

`storefront.get` returns everything the shell needs. It is public and cacheable: fetch it in the root layout with
ISR and a cache tag.

```tsx
// app/layout.tsx (server component)
import { velexis } from "@/lib/velexis";
import { ConsentBanner } from "@/components/ConsentBanner";

const sfOpts = { next: { revalidate: 300, tags: ["velexis:storefront"] } };

export async function generateMetadata() {
  const sf = await velexis.storefront.get({}, sfOpts);
  return {
    title: { template: sf.seo.titleTemplate, default: sf.seo.defaultTitle },
    description: sf.seo.defaultDescription,
    metadataBase: new URL(sf.seo.canonicalBaseUrl),
    openGraph: sf.seo.ogImageUrl ? { images: [sf.seo.ogImageUrl] } : undefined,
    robots: sf.seo.robots, // test keys always return index=false
    icons: { icon: sf.branding.faviconUrl },
  };
}

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const sf = await velexis.storefront.get({}, sfOpts);
  const c = sf.branding.colors;
  return (
    <html lang={sf.defaultLocale} dir={sf.locales.find((l) => l.code === sf.defaultLocale)?.direction}>
      <head>
        <link rel="stylesheet" href={sf.branding.fonts.heading.cssUrl} />
        <link rel="stylesheet" href={sf.branding.fonts.body.cssUrl} />
        <style>{`:root{--primary:${c.primary};--on-primary:${c.onPrimary};--bg:${c.background};--text:${c.text};
          --font-heading:'${sf.branding.fonts.heading.family}';--font-body:'${sf.branding.fonts.body.family}'}`}</style>
      </head>
      <body>
        <Header logo={sf.branding.logoUrl} name={sf.name} accounts={sf.features.customerAccounts}
                locales={sf.locales} currencies={sf.currencies} />
        {children}
        <Footer legal={sf.legal} support={sf.support} />
        {sf.consent.bannerRequired && <ConsentBanner consent={sf.consent} />}
      </body>
    </html>
  );
}
```

What to do with each block:

| Field | Use |
|---|---|
| `features.*` | Hide UI for disabled features (sign-in link if `customerAccounts` is false, guest checkout option, ancillaries/seat steps, upsell step). The API rejects disabled features with `403 FEATURE_DISABLED`. `autoIssue=false` → confirmation page says "tickets will follow". |
| `currencies`, `defaultCurrency`, `locales`, `markets` | Currency/language switchers; store the choice in `vx_currency` / `vx_locale` cookies and pass it as SDK `currency` / `locale` (`X-Currency` / `Accept-Language`). |
| `payment` | Initialise the provider's client library in checkout (never a secret), see the table below. |
| `domains` | Verified storefront hosts (`<key>.velexis.app` and custom domains); validate the request host and redirect secondary hosts to `primaryUrl`. |
| `auth` | Client-side validation of sign-up/reset forms (`passwordPolicy`), verification policy (`emailVerification`; with `required_before_sign_in` sign-up returns no session and the customer is `pending_verification` until verified). |
| `legal` | Footer links; send `legal.termsVersion` back in `auth.signUp`. |
| `consent` | Banner categories, cookie name and lifetime; re-ask when `policyVersion` changes. |
| `seo` | `generateMetadata` defaults. |

`payment` uses exactly the values checkout accepts, so a method or card-brand picker built from it never sends
something `checkout.createPayment` or `flights.price` rejects:

| Field | Values | Use |
|---|---|---|
| `provider` | `stripe` / `adyen` / `checkout_com` / `paypal` — the `Payment.provider` ids | Pick the client library (Stripe.js, Adyen Web, Checkout.com Frames/Flow, PayPal JS SDK); compare with `payment.provider` of a created payment |
| `publishableKey`, `accountId` | provider public key / client id, connected account | Initialise the library |
| `supportedMethods` | subset of `card`, `apple_pay`, `google_pay`, `paypal` — the `method` values of `checkout.createPayment` | Method picker |
| `cardBrands` | Amadeus payment brands (`VISA`, `MASTERCARD`, `AMERICAN_EXPRESS`, `DINERS`, `MAESTRO`, …) | Send as `card.brand` in `checkout.createPayment` and `payments[].brand` in `flights.price` (credit-card fee per brand) |
| `pspCardBrands` | `{ amadeus, psp, label }` per accepted brand | Restrict the provider's card element to the `psp` names; map the brand it detects back to `amadeus` |

```ts
// map the brand detected by the provider's card element (e.g. Stripe "amex") to the Amadeus brand for the card fee
const toAmadeus = (pspBrand: string) => sf.payment.pspCardBrands.find((b) => b.psp === pspBrand)?.amadeus; // undefined → not accepted
```

**Revalidation.** Velexis sends no change notification (there is no settings webhook). With
`next: { revalidate: 300, tags: ["velexis:storefront"] }` settings edits appear within 5 minutes; lower `revalidate`
if you need it faster (the API answers cheaply from Redis). When an edit must show at once, call `revalidateTag`
from an admin-only route handler that **you** protect, and hit it after changing the settings:

```ts
// app/api/admin/revalidate-storefront/route.ts — protected by your own secret, not called by Velexis
import { revalidateTag } from "next/cache";
export async function POST(req: Request) {
  if (req.headers.get("authorization") !== `Bearer ${process.env.REVALIDATE_TOKEN}`) return new Response(null, { status: 401 });
  revalidateTag("velexis:storefront");
  return new Response(null, { status: 204 });
}
```

A suspended OTA answers `403 TENANT_SUSPENDED` — catch it in `app/error.tsx` and render a maintenance page.

### 2.1 One Next.js app for several OTA domains (`storefront.resolve` + hosting key)

A platform or agency that hosts many OTA storefronts in one deployment does not need every OTA's secret key. Create
a **hosting key** (`hk_test_…` / `hk_live_…`) in the Velexis portal for the OTAs you administer (owner or admin),
keep it server-side, and:

1. resolve the visitor's host with `storefront.resolve({ host })` (cache it for `cacheTtlSeconds`; `NOT_FOUND` → 404);
2. send the same hosting key with `host` on every call for that request: the API treats it as that OTA's secret key
   (`X-Velexis-Host`; a missing or foreign host answers `403 HOST_NOT_ALLOWED`);
3. give the browser client the OTA's `publishableKey` from the resolution (and `apiBaseUrl` if set).

```ts
// lib/tenant.ts — server only
import "server-only";
import { headers } from "next/headers";
import { notFound } from "next/navigation";
import { createVelexisClient, isVelexisError, type Schemas } from "@velexis/ota-sdk";
import { endUserFromHeaders } from "@/lib/velexis";

const platform = createVelexisClient({ hostingKey: process.env.VELEXIS_HOSTING_KEY! });
const cache = new Map<string, { at: number; value: Schemas["StorefrontHostResolution"] | null }>();

export async function currentTenant() {
  const host = ((await headers()).get("host") ?? "").split(":")[0].toLowerCase();
  const hit = cache.get(host);
  let value = hit && Date.now() - hit.at < (hit.value?.cacheTtlSeconds ?? 60) * 1000 ? hit.value : undefined;
  if (value === undefined) {
    value = await platform.storefront.resolve({ host }).catch((e) => (isVelexisError(e, "NOT_FOUND") ? null : Promise.reject(e)));
    cache.set(host, { at: Date.now(), value });
  }
  if (!value) notFound();
  return value;
}

/** A client acting as the current host's OTA (same hosting key, tenant chosen by host). */
export async function tenantClient() {
  const t = await currentTenant();
  return platform.withOptions({ host: t.host, baseUrl: t.apiBaseUrl ?? undefined, endUser: endUserFromHeaders });
}

// app/layout.tsx
// const t = await currentTenant();
// const sf = await (await tenantClient()).storefront.get({}, { next: { revalidate: 300, tags: [`velexis:storefront:${t.tenantKey}`] } });
// <Providers publishableKey={t.publishableKey} />   — tag caches per tenant; never share cached data across hosts
```

With per-OTA secret keys (no hosting key) you can still send `host`: the API then checks that the host is a verified
domain of the key's own OTA, which catches mis-routed requests in multi-domain setups.

## 3. Flow: sign-up → verify email → sign-in → session → sign-out

### 3.1 Sign-up (server action)

```tsx
// app/(auth)/sign-up/actions.ts
"use server";
import { redirect } from "next/navigation";
import { isVelexisError } from "@velexis/ota-sdk";
import { velexis, setSessionCookies, endUserFromHeaders } from "@/lib/velexis";

export async function signUpAction(_: unknown, form: FormData) {
  try {
    const res = await velexis.auth.signUp({
      email: String(form.get("email")),
      password: String(form.get("password")),
      firstName: String(form.get("firstName")),
      lastName: String(form.get("lastName")),
      marketingConsent: form.get("marketing") === "on", // unticked by default
      termsVersion: String(form.get("termsVersion")),   // storefront.legal.termsVersion
      returnPath: String(form.get("next") ?? "/account"),
    }, { endUser: await endUserFromHeaders() });        // 5 sign-ups/h per visitor IP, not per server IP
    if (res.session) await setSessionCookies(res.session); // null when verification is required before sign-in
  } catch (e) {
    if (isVelexisError(e, "EMAIL_ALREADY_REGISTERED")) return { error: "You already have an account — sign in or reset your password." };
    if (isVelexisError(e, "PASSWORD_TOO_WEAK")) return { error: e.message, fields: e.fieldErrors };
    if (isVelexisError(e, "VALIDATION_FAILED")) return { fields: e.fieldErrors };
    throw e;
  }
  redirect("/sign-up/check-email");
}
```

The server stores the argon2id hash, default preferences and consent records, and emails a verification link
pointing at the storefront page configured in the settings, e.g. `https://www.acmetravel.com/verify-email?token=vt_…`.

### 3.2 Verify email (page the email links to)

```tsx
// app/verify-email/page.tsx
import { isVelexisError } from "@velexis/ota-sdk";
import { velexis } from "@/lib/velexis";

export default async function VerifyEmail({ searchParams }: { searchParams: Promise<{ token?: string }> }) {
  const { token = "" } = await searchParams;
  try {
    const r = await velexis.auth.verifyEmail({ token });
    return (
      <main>
        <p>{r.verifiedEmail} is confirmed{r.claimedGuestBookings ? ` — ${r.claimedGuestBookings} earlier booking(s) now appear in My trips` : ""}.</p>
        <a href={r.returnPath ?? "/account"}>Continue</a>
      </main>
    );
  } catch (e) {
    if (isVelexisError(e, "VERIFICATION_TOKEN_INVALID")) return <ResendVerificationForm reason={String(e.details?.reason)} />;
    throw e;
  }
}
```

`auth.resendVerification({ email })` always resolves with the same `accepted` message (no account enumeration).

### 3.3 Sign-in

```ts
// app/(auth)/sign-in/actions.ts
"use server";
export async function signInAction(_: unknown, form: FormData) {
  try {
    const { session } = await velexis.auth.signIn({
      email: String(form.get("email")),
      password: String(form.get("password")),
      rememberMe: form.get("remember") === "on", // optional (default true); false → 12 h session
    }, { endUser: await endUserFromHeaders() }); // lockout counters + session user agent / IP country of the visitor
    await setSessionCookies(session);
  } catch (e) {
    if (isVelexisError(e, "INVALID_CREDENTIALS")) return { error: "Email or password is wrong." };
    if (isVelexisError(e, "ACCOUNT_LOCKED")) return { error: e.message };          // 423, details.lockedUntil
    if (isVelexisError(e, "EMAIL_NOT_VERIFIED")) return { error: "Confirm your email — we sent a new link." };
    if (isVelexisError(e, "RATE_LIMITED")) return { error: "Too many attempts, try again shortly." };
    throw e;
  }
  redirect(String(form.get("next") ?? "/account"));
}
```

### 3.4 Keep the session fresh (middleware + `auth.refresh`)

Access tokens live 15 minutes; refresh tokens rotate on every use (a replayed old token revokes the whole family:
`REFRESH_TOKEN_REUSED`). Refresh in middleware so server components always see a valid token.

```ts
// middleware.ts
import { NextResponse, type NextRequest } from "next/server";
import { createVelexisClient, isVelexisError } from "@velexis/ota-sdk";

const velexis = createVelexisClient({ secretKey: process.env.VELEXIS_SECRET_KEY! });
const cookie = { httpOnly: true, secure: true, sameSite: "lax" as const, path: "/" };

export async function middleware(req: NextRequest) {
  const at = req.cookies.get("vx_at")?.value;
  const rt = req.cookies.get("vx_rt")?.value;
  if (at || !rt) return NextResponse.next(); // the vx_at cookie disappears 60 s before the token expires
  try {
    const { session: s } = await velexis.auth.refresh(
      { refreshToken: rt },
      { endUser: { ip: req.headers.get("x-forwarded-for")?.split(",")[0]?.trim(), userAgent: req.headers.get("user-agent") ?? undefined } },
    ); // returns { session, customer } like auth.signIn
    req.cookies.set("vx_at", s.accessToken); // visible to server components rendering this request
    req.cookies.set("vx_rt", s.refreshToken);
    const res = NextResponse.next({ request: { headers: req.headers } });
    res.cookies.set("vx_at", s.accessToken, { ...cookie, expires: new Date(Date.parse(s.accessTokenExpiresAt) - 60_000) });
    res.cookies.set("vx_rt", s.refreshToken, { ...cookie, expires: new Date(s.refreshTokenExpiresAt) });
    return res;
  } catch (e) {
    const res = NextResponse.next();
    if (isVelexisError(e, "REFRESH_TOKEN_INVALID") || isVelexisError(e, "REFRESH_TOKEN_REUSED")) res.cookies.delete("vx_rt");
    return res;
  }
}
export const config = { matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"] };
```

Parallel refreshes (several tabs, prefetches) with the same refresh token within 10 seconds receive the same new
pair, so the middleware does not need its own lock. `auth.refresh` returns `AuthSessionResult` (`{ session, customer }`),
the same shape as `auth.signIn` / `auth.changePassword` and like `console.auth.refresh`'s wrapper, so one helper can
store `result.session` for every flow; the SDK's automatic refresh hands `result.session` to `onSessionRefreshed`.

### 3.5 Who is signed in (`auth.getSession`)

```tsx
// components/AccountMenu.tsx (server component)
import { isVelexisError } from "@velexis/ota-sdk";
import { customerClient } from "@/lib/velexis";

export async function AccountMenu() {
  const v = await customerClient();
  const me = await v.auth.getSession().catch((e) => {
    if (isVelexisError(e, "UNAUTHENTICATED") || isVelexisError(e, "TOKEN_EXPIRED")) return null;
    throw e;
  });
  return me ? <a href="/account">Hi {me.customer.firstName}</a> : <a href="/sign-in">Sign in</a>;
}
```

Personal responses are never cached; the SDK sends `cache: "no-store"` for `auth.*` and `account.*`.

### 3.6 Sign-out, password reset, password change

```ts
"use server";
export async function signOutAction(scope: "current" | "all" = "current") {
  const jar = await cookies();
  const v = await customerClient();
  await v.auth.signOut({ scope, refreshToken: jar.get(RT)?.value }).catch(() => undefined);
  await clearSessionCookies();
  redirect("/");
}

export async function forgotPasswordAction(form: FormData) {
  const r = await velexis.auth.requestPasswordReset({ email: String(form.get("email")) }, { endUser: await endUserFromHeaders() });
  return { message: r.message }; // same answer whether or not the account exists; 10 requests/h per visitor IP
}

export async function resetPasswordAction(token: string, form: FormData) {
  try {
    // signIn is optional (default true)
    const r = await velexis.auth.resetPassword({ token, newPassword: String(form.get("password")) }, { endUser: await endUserFromHeaders() });
    if (r.session) await setSessionCookies(r.session); // all older sessions were revoked
  } catch (e) {
    if (isVelexisError(e, "PASSWORD_RESET_TOKEN_INVALID")) return { error: "This link has expired — request a new one." };
    if (isVelexisError(e, "PASSWORD_TOO_WEAK")) return { error: e.message };
    throw e;
  }
  redirect("/account");
}

export async function changePasswordAction(_: unknown, form: FormData) {
  const v = await customerClient();
  try {
    const { session } = await v.auth.changePassword({
      currentPassword: String(form.get("current")),
      newPassword: String(form.get("next")),
      signOutOtherSessions: true,
    });
    await setSessionCookies(session); // the current session was rotated
    return { ok: true };
  } catch (e) {
    if (isVelexisError(e, "CURRENT_PASSWORD_INCORRECT") || isVelexisError(e, "PASSWORD_TOO_WEAK")) return { error: e.message };
    throw e;
  }
}
```

## 4. Flow: account, preferences, saved travellers, privacy

### 4.1 Profile with optimistic concurrency

Every versioned resource (`Customer`, `CustomerPreferences`, `SavedTraveler`) has a `version`; pass it as `ifMatch`
on update (sent as `If-Match: "<version>"`). A stale value throws `PRECONDITION_FAILED` (412): reload and retry.

```tsx
// app/account/page.tsx
export default async function AccountPage() {
  const v = await customerClient();
  const [me, prefs] = await Promise.all([v.account.get(), v.account.preferences.get()]);
  return <ProfileForm customer={me} preferences={prefs} />;
}

// app/account/actions.ts
"use server";
export async function saveProfile(version: number, form: FormData) {
  const v = await customerClient();
  try {
    await v.account.update({
      ifMatch: version,
      firstName: String(form.get("firstName")),
      lastName: String(form.get("lastName")),
      phone: { deviceType: "MOBILE", countryCallingCode: String(form.get("cc")), number: String(form.get("phone")) },
      marketingConsent: form.get("marketing") === "on",
    });
  } catch (e) {
    if (isVelexisError(e, "PRECONDITION_FAILED")) return { error: "Your profile changed in another tab — reload." };
    throw e;
  }
  revalidatePath("/account");
}

export async function changeEmail(version: number, form: FormData) {
  const v = await customerClient();
  // becomes pendingEmail; a link is sent to the new address and confirmed with auth.verifyEmail
  await v.account.update({ ifMatch: version, email: String(form.get("email")), currentPassword: String(form.get("password")) });
}
```

### 4.3 Saved travellers and checkout

Saved travellers use `AmadeusTraveler` / `AmadeusIdentityDocument` field names. Lists show masked document
numbers; a single traveller has full numbers and an `amadeus` projection (an `AmadeusTraveler` without `id`).

```tsx
// Checkout traveller picker (server component)
export async function TravelerPicker({ count }: { count: number }) {
  const v = await customerClient();
  const page = await v.account.savedTravelers.list({ limit: 20 });
  return <PickTravelers travelers={page.data} count={count} />; // shows name, DOB, numberMasked, expiryStatus warnings
}
```

In checkout, pass the chosen `savedTravelerId` (`trv_…`; documents are `tdc_…`, the prefixes of the
`saved_travelers` / `saved_traveler_documents` rows) to the checkout traveller step (see the B3 guide) — the
server copies the stored data, including full document numbers, into the Amadeus traveller. To pre-fill an editable
form instead, load one traveller and use `amadeus` directly:

```ts
const t = await v.account.savedTravelers.get({ savedTravelerId: "trv_7Gd2Kp9Lq4Mx8Nz3" });
const formDefaults = t.amadeus; // { name, dateOfBirth, gender, documents[], contact, emergencyContact, loyaltyPrograms }
```

Create / update / delete:

```ts
"use server";
export async function saveTraveler(form: FormData) {
  const v = await customerClient();
  try {
    await v.account.savedTravelers.create({                     // isAccountHolder and documents[].holder are optional
      label: String(form.get("label") ?? ""),
      name: { firstName: "LEO", lastName: "BERG" },               // as in the passport MRZ
      dateOfBirth: "2019-06-02",
      gender: "MALE",
      documents: [{ documentType: "PASSPORT", number: "128840457", expiryDate: "2027-01-15",

                issuanceCountry: "GB", nationality: "GB", holder: true }],
});
await v.account.savedTravelers.delete({ savedTravelerId: t.id });
```

## 5. Flow: reference data in the search form and results

### 5.1 Airport / city autocomplete (client component)

```tsx
"use client";
import { useEffect, useState } from "react";
import type { Schemas } from "@velexis/ota-sdk";
import { browserClient } from "@/lib/velexis-browser";

export function LocationInput({ onPick }: { onPick: (code: string, subType: "AIRPORT" | "CITY") => void }) {
  const [q, setQ] = useState("");
  const [items, setItems] = useState<Schemas["Location"][]>([]);
  useEffect(() => {
    if (q.trim().length < 2) { setItems([]); return; }
    const ctrl = new AbortController();
    const t = setTimeout(() => {
      browserClient.reference.locations
        .search({ keyword: q, subType: ["AIRPORT", "CITY"], limit: 8 }, { signal: ctrl.signal })
        .then((p) => setItems(p.data))
        .catch(() => undefined); // ABORTED for stale requests
    }, 200);
    return () => { clearTimeout(t); ctrl.abort(); };
  }, [q]);
  return (
    <div role="combobox" aria-expanded={items.length > 0}>
      <input value={q} onChange={(e) => setQ(e.target.value)} placeholder="From" />
      <ul>
        {items.map((l) => (
          <li key={l.id} onClick={() => onPick(l.iataCode, l.subType)}>
            {l.detailedName}
            {l.subType === "CITY" && <small> (all airports: {l.airports.map((a) => a.iataCode).join(", ")})</small>}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Put the picked `iataCode` into the flight search origin/destination and `subType` into its location sub-type
(a CITY code searches all airports of the city).

Matching is an exact IATA code plus a case-insensitive **prefix** match on the English airport, airport-city and city
names, ranked by popularity — what the `reference` schema's btree `lower(...)` indexes support. There is no fuzzy,
accent-insensitive or translated matching (`mun` finds Munich, `münchen` finds nothing), so label the field
"City, airport or code" rather than promising free-text search.

### 5.2 Airline names and logos on the results page (server component)

Result pages of `flights.listResults` already carry `dictionaries.carriers` (name, `logoUrl`) for every carrier on
the page — use them first. `FlightOffer.amadeus` is omitted in the default `summary` view, so never read carriers from

```tsx
const byCode = new Map(airlines.map((a) => [a.iataCode, a]));
// <img src={byCode.get(code)?.logoSquareUrl} alt={name(code)} width={32} height={32} /> {byCode.get(code)?.alliance}
```

## 6. Error handling

All errors are `VelexisError` subclasses with `code`, `status`, `message` (localised, safe to show),
`fieldErrors` and `requestId`. Branch on `code` with `isVelexisError(e, code)`.

| Code | Status | Class | Thrown by | What the UI should do |
|---|---|---|---|---|
| `VALIDATION_FAILED` | 400 | ValidationError | all writes | Show `fieldErrors[].path` next to the fields |
| `VERIFICATION_TOKEN_INVALID` | 400 | ValidationError | auth.verifyEmail | Offer "send a new link" (`details.reason`) |
| `PASSWORD_RESET_TOKEN_INVALID` | 400 | ValidationError | auth.resetPassword | Offer a new reset email |
| `INVALID_CREDENTIALS` | 401 | AuthenticationError | auth.signIn | Generic "email or password is wrong" |
| `UNAUTHENTICATED` / `TOKEN_EXPIRED` | 401 | AuthenticationError | account.*, auth.getSession, auth.changePassword | Redirect to sign-in (the SDK refreshes once on `TOKEN_EXPIRED` first) |
| `REFRESH_TOKEN_INVALID` / `REFRESH_TOKEN_REUSED` | 401 | AuthenticationError | auth.refresh | Clear cookies, sign in again |
| `INVALID_API_KEY` | 401 | AuthenticationError | all | Configuration error (wrong key/environment) |
| `EMAIL_NOT_VERIFIED` | 403 | PermissionError | auth.signIn | "Check your inbox" (a new link was sent) |
| `FEATURE_DISABLED` | 403 | PermissionError | auth.*, account.savedTravelers.* | Hide the feature (see `storefront.features`) |
| `ORIGIN_NOT_ALLOWED` | 403 | PermissionError | browser calls | Add the origin to the publishable key's allow-list |
| `TENANT_SUSPENDED` | 403 | PermissionError | all | Maintenance page |
| `HOST_NOT_ALLOWED` | 403 | PermissionError | all except storefront.resolve | Hosting key without `host`, or a host that is not a verified domain of an OTA the key may act for (`details.reason`) — answer 404 for that host |
| `SCOPE_NOT_ALLOWED` | 403 | PermissionError | storefront.resolve | Called with a publishable key; call it server-side with the hosting/secret key |
| `NOT_FOUND` | 404 | NotFoundError | get/update/delete by id, storefront.resolve (unknown host) | `notFound()` |
| `EMAIL_ALREADY_REGISTERED` | 409 | ConflictError | auth.signUp, account.update, auth.verifyEmail | Offer sign-in / reset |
| `ACCOUNT_DELETION_BLOCKED` | 409 | ConflictError | account.delete | List `details.bookingIds`, retry later |
| `IDEMPOTENCY_KEY_REUSED` | 409 | ConflictError | POSTs | Bug: a key was reused with a different body |
| `PRECONDITION_FAILED` | 412 | VelexisError | account.update, preferences.update, savedTravelers.update | Reload, re-apply, retry |
| `PASSWORD_TOO_WEAK` | 422 | ValidationError | signUp, resetPassword, changePassword | Show `details.violations` |
| `CURRENT_PASSWORD_INCORRECT` | 422 | ValidationError | changePassword, account.update (email), account.delete | Field error on current password |
| `TRAVELER_DATA_INVALID` | 422 | ValidationError | savedTravelers.create/update | Field errors |
| `SAVED_TRAVELER_LIMIT_REACHED` | 422 | ValidationError | savedTravelers.create | "Delete a traveller first" (max 20) |
| `ACCOUNT_LOCKED` | 423 | VelexisError | auth.signIn, auth.changePassword | Show `details.lockedUntil`, offer reset |
| `RATE_LIMITED` | 429 | RateLimitError | all | Wait `retryAfterSeconds` |
| `INTERNAL_ERROR` | 500 | ServerError | all | Error page quoting `requestId` |

The SDK retries 429/503/504 and network errors automatically for GETs and for POSTs carrying an `Idempotency-Key`
(generated by the SDK when you do not pass `options.idempotencyKey`).

## 8. Implementation notes (NestJS)

- **Modules:** `StorefrontModule`, `AuthModule`, `AccountModule`, `ReferenceModule`. Every request resolves the tenant
  from `X-Api-Key` (or host), then runs in a transaction with `SET LOCAL search_path TO tenant_<key>, reference`.
- **Hosting keys and `X-Velexis-Host`:** a hosting key (`hk_…`) resolves the tenant from the verified storefront
  domain in `X-Velexis-Host` (`platform.tenant_domains`, purpose storefront, verified) after checking that the key is
  granted for that tenant, then behaves exactly like the tenant's secret key of the same environment; missing, unknown
  or foreign hosts → `403 HOST_NOT_ALLOWED`. With pk/sk keys the header is optional and must match the key's tenant.
  Platform follow-up: `platform.api_keys` needs a `hosting` kind with per-tenant grants, and the storefront publishable
  key must stay displayable for `storefront.resolve` (publishable keys are public).
- **End user on server calls:** for secret and hosting keys the guard takes the client IP and user agent from
  `X-Velexis-End-User-IP` / `X-Velexis-End-User-Agent` (ignored for publishable keys); rate limits, sign-in failure
  counters, `customer_sessions` metadata and the hashed IP in `customer_consents` use that end-user context.
- **Request defaults:** request-body defaults are stated in the field descriptions, not as JSON Schema `default`
  (openapi-typescript would turn a defaulted field into a required TypeScript property); NestJS DTOs apply them.
- **IDs:** `cus_`, `ses_`, `trv_` (saved travellers), `tdc_` (their documents), `dex_` (data exports) + 16–40
  alphanumeric characters (ULID), matching the tenant-table CHECKs and the other areas.
- **Passwords:** argon2id; breached-password check by k-anonymity range query; unknown emails run a dummy verify.
- **Tokens:** access token = RS256 JWT with per-tenant key (`kid`), claims `sub` (cus_…), `sid` (ses_…), `ten`, `env`,
  `scope=customer`, 15 min. Refresh token = 256-bit opaque `rt_…`, stored as SHA-256 hash with a `family_id` in
  `customer_sessions`; rotation on every refresh, reuse → family revoked; 10-second grace + Redis lock for concurrent
  refreshes; revoked `sid`s on a Redis deny-list for 15 minutes.
- **One-time tokens:** verification (`vt_…`, 24 h, in `customer_identities`) and reset (`pr_…`, 60 min, in
  `customer_password_resets`), stored hashed, single use.
- **Saved-traveller documents:** numbers encrypted with the tenant's data key; only the last 4 characters in clear.
- **Rate limits (Redis, keyed by the end-user IP described above):** sign-in 20/min/IP and 10/min/email, lockout after
  5 failures for 15 min; sign-up 5/h per IP and per email; reset 10/h/IP; reference 20/s per key and IP.
- **Reference search:** prefix matching only (`lower(name) LIKE lower($1) || '%'` on btree `text_pattern_ops`
  indexes of airports.name, airports.city_name and cities.name) plus exact IATA codes, ordered by `search_rank`;
  `pg_trgm`/`unaccent` are not available and the reference tables hold one English name per entry.
- **Caching:** storefront config in Redis 5 min per tenant + environment + locale, invalidated on settings save (no
  outbound webhook — storefronts revalidate on a timer); reference search results 24 h; HTTP `Cache-Control` as
  documented per operation; personal data `private, no-store`.
