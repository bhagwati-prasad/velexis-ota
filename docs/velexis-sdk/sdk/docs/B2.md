# Flight shopping with `velexis.flights` (Next.js App Router)

The `flights` namespace of `@velexis/ota-sdk` covers everything between the search form and the checkout:

| Step | SDK method | Result |
|---|---|---|
| Search form → results | `flights.search` | `FlightSearch` (`srch_…`) with the first page of offers, facets, highlights |
| Results page (filters, sort, pages) | `flights.listResults`, `flights.getSearch` | `FlightResultsPage` (`Page<FlightOffer>` + `facets`) |
| Offer details | `flights.getOffer` | `FlightOffer` (`off_…`) in full view |
| Fare-family picker | `flights.upsell` | `UpsellResult` (`ups_…`): new offers + comparison table |
| Confirm price | `flights.price`, `flights.getPricedOffer` | `PricedOffer` (`prc_…`): confirmed price, requirements, card fees |
| Extras | `flights.getAncillaries` (+ `flights.price` with `additionalServices`) | `AncillaryCatalogue` (`anc_…` options) |
| Fare conditions | `flights.getFareRules` | `FareRuleSet` |
| Console availability screen | `flights.availability` | booking classes and seats per class |

The priced offer id (`prc_…`) is what you hand to the checkout namespace to collect travellers, contacts and payment.

You never send Amadeus offers back to Velexis: every Amadeus offer is stored server-side (tenant tables `flight_offers`, `priced_offers`) and you refer to it by id.

## 1. Keys, tokens and where to call what

| Caller | Key | Token | Can call | Scope (what the response contains) |
|---|---|---|---|---|
| Client component (browser) | publishable `pk_…` | customer token (optional) | everything except `availability` | customer: selling amounts only |
| Server component, server action, route handler | secret `sk_…` | customer token (optional) | everything | **customer**: selling amounts only, the same as the browser |
| Console backend / automation | secret `sk_…` + header `X-Velexis-Scope: console` | none | everything | console: adds `netPrice`, `markup`, verbatim Amadeus payloads, `diagnostics`, read access to every customer's searches and priced offers |
| Console (staff) | secret `sk_…` | staff token | everything | console (send `X-Velexis-Scope: customer` to preview the shopper view) |

- **A secret key alone is customer scope.** Storefront server code can pass `FlightSearch`, `FlightOffer`, `UpsellResult` and `PricedOffer` objects to client components without leaking net cost: `amadeus.price` already carries selling amounts, and `netPrice` / `markup` / `diagnostics` are absent. Console scope needs a staff token, or a secret key without customer token that sends `X-Velexis-Scope: console` (per call `{ headers: { "X-Velexis-Scope": "console" } }`, or as client `headers` in a console-only client). Sending that header with a publishable key or a customer token fails with `403 SCOPE_NOT_ALLOWED`. (`toCustomerView()` from `@velexis/ota-sdk/next` stays useful as a defence in depth.)
- Anonymous shoppers can search, upsell and price. A customer token links searches and priced offers to the customer. After that, only that customer's token, or console scope, can read them. A plain secret key without the token gets `404`.
- Prices are live and expire (search results about 30 min after the search completes, priced offers after about 20 min). The SDK sends `cache: "no-store"` for every `flights.*` call. **Never** pass `next: { revalidate }` to these methods.
- `search`, `upsell`, `availability` and `price` store rows (`flight_searches`, `offer_upsells`, `priced_offers`), so they require an `Idempotency-Key`. The SDK generates one per call (`RequestOptions.idempotencyKey` overrides it). Its automatic retries on `503`/`504`/network errors replay the stored result, with the same `srch_…` / `prc_…` ids, instead of running the call twice. A new call is a new search or snapshot.
- Synchronous searches take several seconds (up to 60 s), so pass `timeoutMs: 60_000`. Where function time limits are short, use an asynchronous search instead (section 2).

```ts
// lib/velexis.ts — server-side client (server components, server actions, route handlers)
import "server-only";
import { cookies } from "next/headers";
import { createVelexisClient } from "@velexis/ota-sdk";
import { DEFAULT_COOKIE_NAMES } from "@velexis/ota-sdk/next";

export function velexisServer() {
  return createVelexisClient({
    secretKey: process.env.VELEXIS_SECRET_KEY!, // customer scope: selling amounts only
    // customer session, if any (`vx_at`, the cookie the @velexis/ota-sdk/next auth handlers write)
    accessToken: async () => (await cookies()).get(DEFAULT_COOKIE_NAMES.accessToken)?.value ?? null,
    locale: "en-GB",
    currency: "EUR",
  });
}

// lib/velexis-browser.ts — browser client (client components)
"use client";
import { createVelexisClient } from "@velexis/ota-sdk";
export const velexis = createVelexisClient({ publishableKey: process.env.NEXT_PUBLIC_VELEXIS_PUBLISHABLE_KEY! });
```

These use the same cookie (`vx_at`) and environment variables (`VELEXIS_SECRET_KEY`, `NEXT_PUBLIC_VELEXIS_PUBLISHABLE_KEY`) as the `@velexis/ota-sdk/next` helpers. `createServerClient()` and `createBrowserClient()` from that module are ready-made equivalents that also refresh tokens. The examples below use the two helpers above.

## 2. Search: server action + redirect

SIMPLE mode takes exactly the Amadeus GET parameters. ADVANCED mode takes the full Amadeus POST body in `query`. Use ADVANCED for multi-city trips, flexible dates (`dateWindow`), time windows, cabin per leg, connection limits, corporate codes and similar options.

```ts
// app/flights/actions.ts
"use server";
import { redirect } from "next/navigation";
import { velexisServer } from "@/lib/velexis";
import { isVelexisError } from "@velexis/ota-sdk";

export async function searchFlights(_: unknown, form: FormData) {
  try {
    const search = await velexisServer().flights.search(
      {
        mode: "simple",
        originLocationCode: String(form.get("from")),        // "PAR"
        destinationLocationCode: String(form.get("to")),     // "NYC"
        departureDate: String(form.get("depart")),           // "2026-11-20"
        returnDate: (form.get("return") as string) || undefined,
        adults: Number(form.get("adults") ?? 1),
        children: Number(form.get("children") ?? 0),
        infants: Number(form.get("infants") ?? 0),
        travelClass: "ECONOMY",
        nonStop: form.get("nonStop") === "on",
        resultOptions: { limit: 0 },                         // the results page loads page 1 itself
      },
      { timeoutMs: 60_000 },
    );
    redirect(`/flights/results/${search.id}`);
  } catch (e) {
    if (isVelexisError(e, "VALIDATION_FAILED") || isVelexisError(e, "UNPROCESSABLE")) {
      return { error: e.message, fieldErrors: e.fieldErrors };
    }
    if (isVelexisError(e, "SUPPLIER_TIMEOUT") || isVelexisError(e, "SUPPLIER_UNAVAILABLE")) {
      return { error: "Airlines are not answering right now, please try again." };
    }
    throw e; // error.tsx
  }
}
```

Multi-city in ADVANCED mode:

```ts
await velexisServer().flights.search({
  mode: "advanced",
  query: {
    originDestinations: [
      { id: "1", originLocationCode: "PAR", destinationLocationCode: "NYC", departureDateTimeRange: { date: "2026-11-20", time: "10:00:00", timeWindow: "4H" } },
      { id: "2", originLocationCode: "NYC", destinationLocationCode: "MIA", departureDateTimeRange: { date: "2026-11-24", dateWindow: "I1D" } },
      { id: "3", originLocationCode: "MIA", destinationLocationCode: "PAR", departureDateTimeRange: { date: "2026-11-29" } },
    ],
    travelers: [{ id: "1", travelerType: "ADULT" }, { id: "2", travelerType: "HELD_INFANT", associatedAdultId: "1" }],
    sources: ["GDS"],
    searchCriteria: {
      maxFlightOffers: 100,
      additionalInformation: { brandedFares: true, chargeableCheckedBags: true, fareRules: true },
      flightFilters: {
        cabinRestrictions: [{ cabin: "BUSINESS", coverage: "MOST_SEGMENTS", originDestinationIds: ["1", "3"] }],
        // the complete Amadeus ConnectionRestriction, incl. nonStopPreferred / nonStopPreferredWeight
        connectionRestriction: { maxNumberOfConnections: 1, nonStopPreferred: true, nonStopPreferredWeight: 60 },
      },
    },
  },
}, { timeoutMs: 60_000 });
```

If you leave out `additionalInformation`, Velexis turns on `brandedFares`, `chargeableCheckedBags` and `fareRules`. This keeps the branded-fare, bag and refundability facets populated.

### Asynchronous search (serverless time limits, progress screens)

By default `flights.search` waits for Amadeus (typically 2–15 s, up to 60 s). That can exceed short serverless function limits. With `resultOptions: { async: true }` the API answers `202` at once with `status: "pending"` and `retryAfterSeconds`, and runs Amadeus in the background. Poll `flights.getSearch` until the status is `completed` (then load results with `listResults`) or `failed` (`error.code`, e.g. `SUPPLIER_TIMEOUT`). Validation and permission errors are still thrown by `search` itself.

```ts
// app/flights/actions.ts — returns in ~100 ms, no maxDuration needed
export async function searchFlightsAsync(_: unknown, form: FormData) {
  const pending = await velexisServer().flights.search({
    mode: "simple",
    originLocationCode: String(form.get("from")),
    destinationLocationCode: String(form.get("to")),
    departureDate: String(form.get("depart")),
    adults: Number(form.get("adults") ?? 1),
    resultOptions: { async: true },
  });
  redirect(`/flights/results/${pending.id}`); // pending.status === "pending"
}
```

```tsx
// app/flights/results/[searchId]/progress.tsx — shown while the search is pending
"use client";
import { useEffect } from "react";
import { useRouter } from "next/navigation";
import { velexis } from "@/lib/velexis-browser";

export function SearchProgress({ searchId, retryAfterSeconds }: { searchId: string; retryAfterSeconds: number }) {
  const router = useRouter();
  useEffect(() => {
    let timer: ReturnType<typeof setTimeout>;
    const poll = async (delay: number) => {
      timer = setTimeout(async () => {
        const s = await velexis.flights.getSearch({ searchId });
        if (s.status === "pending") poll((s.retryAfterSeconds ?? 2) * 1000);
        else router.refresh(); // the server component now renders results (completed) or an error (failed)
      }, delay);
    };
    poll(retryAfterSeconds * 1000);
    return () => clearTimeout(timer);
  }, [searchId, retryAfterSeconds, router]);
  return <p>Searching airlines…</p>;
}
```

Until the search completes, `listResults` throws `SEARCH_NOT_COMPLETED` (409, `details.status`, `details.retryAfterSeconds`).

## 3. Results page: server component + client-side filtering

The server component renders the first page. The client component then re-queries `listResults` with the publishable key as the user changes filters. Velexis does all filtering, sorting and faceting from the stored offers, without calling Amadeus.

```tsx
// app/flights/results/[searchId]/page.tsx (server component)
import { velexisServer } from "@/lib/velexis";
import { Results } from "./results";

export default async function Page({ params }: { params: Promise<{ searchId: string }> }) {
  const { searchId } = await params;
  const vx = velexisServer();
  const search = await vx.flights.getSearch({ searchId });
  if (search.status === "expired") {
    return <ExpiredBanner criteria={search.criteria.request} />; // re-run flights.search with the same criteria
  }
  if (search.status === "pending") return <SearchProgress searchId={searchId} retryAfterSeconds={search.retryAfterSeconds ?? 2} />;
  if (search.status === "failed") return <SearchFailed code={search.error?.code} criteria={search.criteria.request} />;
  // secret key = customer scope: the offers carry selling amounts only and can go straight to the client component
  const first = await vx.flights.listResults({ searchId, sort: "best", limit: 20 });
  return (
    <Results
      searchId={searchId}
      summary={search.summary}
      highlights={search.highlights}
      initial={{ data: first.data, facets: first.facets, nextCursor: first.page.nextCursor, total: first.total }}
    />
  );
}
```

```tsx
// app/flights/results/[searchId]/results.tsx
"use client";
import { useEffect, useState, useTransition } from "react";
import { velexis } from "@/lib/velexis-browser";
import type { FlightOffer, FlightFacets, FlightResultFilters, FlightOfferSort, FlightSearch } from "@velexis/ota-sdk";
import { isVelexisError } from "@velexis/ota-sdk";

type TimeBand = NonNullable<FlightFacets["departureTimes"]>[number];

export function Results({ searchId, initial }: {
  searchId: string;
  summary: FlightSearch["summary"];
  highlights: FlightSearch["highlights"];
  initial: { data: FlightOffer[]; facets: FlightFacets; nextCursor: string | null; total: number };
}) {
  const [filters, setFilters] = useState<FlightResultFilters>({});
  const [sort, setSort] = useState<FlightOfferSort>("best");
  const [offers, setOffers] = useState(initial.data);
  const [facets, setFacets] = useState(initial.facets);
  const [cursor, setCursor] = useState(initial.nextCursor);
  const [expired, setExpired] = useState(false);
  const [pending, start] = useTransition();

  useEffect(() => {
    start(async () => {
      try {
        // Changing filters or sort: always start without a cursor.
        const page = await velexis.flights.listResults({ searchId, ...filters, sort, limit: 20 });
        setOffers(page.data); setFacets(page.facets); setCursor(page.page.nextCursor);
      } catch (e) {
        if (isVelexisError(e, "SEARCH_EXPIRED")) setExpired(true); else throw e;
      }
    });
  }, [searchId, filters, sort]);

  async function loadMore() {
    if (!cursor) return;
    const page = await velexis.flights.listResults({ searchId, ...filters, sort, cursor, limit: 20 });
    setOffers((o) => [...o, ...page.data]); setCursor(page.page.nextCursor);
  }

  // Facets come with ready-made time bands: send `${band.itineraryIndex}:${band.from}-${band.to}`.
  // Bands are multi-select: windows of the same itinerary are ORed, windows of different itineraries ANDed.
  const toggleBand = (b: TimeBand) =>
    setFilters((f) => {
      const w = `${b.itineraryIndex}:${b.from}-${b.to}` as const;
      const current = f.departureWindow ?? [];
      const next = current.includes(w) ? current.filter((x) => x !== w) : [...current, w];
      return { ...f, departureWindow: next.length ? next : undefined };
    });

  /* render: sidebar from facets.stops / carriers / price / departureTimes / brandedFares / includedCheckedBags /
     refundable; cards from offer.summary + offer.itineraries; "Load more" → loadMore(); expired → banner */
  return null;
}
```

Filter semantics:

| Parameter | Meaning |
|---|---|
| `stops` | `[0]` keeps only non-stop offers; `[0, 1]` keeps offers with up to 1 stop; `2` means 2 or more |
| `carriers` | All marketing carriers of the offer must be in the list |
| `minPrice` / `maxPrice` | Selling total for all travellers, as a decimal string |
| `departureWindow` / `arrivalWindow` | `"{itineraryIndex}:{HH:MM}-{HH:MM}"` in local airport time. Several windows of the **same** itinerary are ORed (e.g. morning or evening). Windows of different itineraries are ANDed. At most 24 |
| `maxDurationMinutes` | Every itinerary must be at most this long |
| `cabins` | Main cabin (the cabin of the longest segment) |
| `minIncludedCheckedBags` | Included checked bags per adult on every segment |
| `refundable` / `changeable` | Only offers whose conditions are **known**; offers with unknown conditions are excluded when the filter is set |
| `brandedFares` | Fare family codes from the `brandedFares` facet |

Each facet group counts the offers that match **all other** active filters (disjunctive faceting). So "Air France (41) from €1,240" stays visible while the Air France box is checked. Time-band facets work per itinerary: the outbound bands ignore the outbound windows but apply the return windows, so several outbound bands can be ticked together.

On the wire, array filters are comma-separated, like every list endpoint of the API: `GET /v1/flight-searches/{id}/offers?stops=0,1&carriers=AF,KL&departureWindow=0:06:00-11:59,0:18:00-23:59,1:18:00-23:59`. The SDK does this for you.

## 4. Offer details and branded-fare upsell

```tsx
// app/flights/offers/[offerId]/page.tsx
import { velexisServer } from "@/lib/velexis";
import { isVelexisError } from "@velexis/ota-sdk";
import { notFound, redirect } from "next/navigation";
import { FarePicker } from "./fare-picker";

export default async function OfferPage({ params }: { params: Promise<{ offerId: string }> }) {
  const { offerId } = await params;
  try {
    const offer = await velexisServer().flights.getOffer({ offerId });
    // offer.itineraries[].segments[] (operating carrier, aircraft, layovers, CO2)
    // offer.travelerPricings[].segments[] (cabin, fareBasis, brandedFareLabel, class, included bags, amenities)
    // offer.price.breakdown (taxes by code, fees) — still the *search* price
    return <FarePicker offer={offer} />;
  } catch (e) {
    if (isVelexisError(e, "OFFER_EXPIRED")) redirect("/flights?expired=1");
    if (isVelexisError(e, "NOT_FOUND")) notFound();
    throw e;
  }
}
```

```tsx
// app/flights/offers/[offerId]/fare-picker.tsx
"use client";
import { useEffect, useState } from "react";
import { velexis } from "@/lib/velexis-browser";
import type { FlightOffer, UpsellResult } from "@velexis/ota-sdk";
import { priceOffer } from "../../price-actions";

export function FarePicker({ offer }: { offer: FlightOffer }) {
  const [upsell, setUpsell] = useState<UpsellResult | null>(null);
  useEffect(() => { velexis.flights.upsell({ offerId: offer.id }).then(setUpsell).catch(() => setUpsell(null)); }, [offer.id]);
  // upsell?.comparison.columns → one column per fare family (base first, priceDifference)
  // upsell?.comparison.rows    → checked_bags / seat_selection / change / refund … with included | chargeable | not_offered
  // The user picks a column → priceOffer(column.offerId, column.price)
  return null;
}
```

Upsell results are cached per offer and payment input, so calling `upsell` again returns the same `ups_…` and `off_…` ids. Upsell offers expire together with the search.

## 5. Pricing: confirmed price, PRICE_CHANGED and booking requirements

```ts
// app/flights/price-actions.ts
"use server";
import { redirect } from "next/navigation";
import { velexisServer } from "@/lib/velexis";
import { PriceChangedError, SoldOutError, isVelexisError, type Money } from "@velexis/ota-sdk";

export async function priceOffer(offerId: string, shownTotal: Money) {
  let pricedOfferId: string;
  try {
    const priced = await velexisServer().flights.price({
      offerIds: [offerId],
      include: ["bags", "other-services", "detailed-fare-rules"],
      expectedTotal: shownTotal, // throws PRICE_CHANGED if the confirmed total differs
    });
    pricedOfferId = priced.id;
  } catch (e) {
    if (e instanceof PriceChangedError) {
      // The priced offer *was* stored: show the new price and let the customer accept it.
      // oldPrice / newPrice / pricedOfferId are typed on the error — no cast of e.details needed.
      return { priceChanged: { old: e.oldPrice, new: e.newPrice, pricedOfferId: e.pricedOfferId } };
    }
    if (e instanceof SoldOutError) return { soldOut: true };
    if (isVelexisError(e, "OFFER_EXPIRED")) redirect("/flights?expired=1");
    throw e;
  }
  redirect(`/flights/review/${pricedOfferId}`);
}
```

If you leave out `expectedTotal`, the call always resolves. Compare `priced.priceChange.changed`, `oldPrice`, `newPrice` and `direction` yourself.

The review page reads the priced offer and uses `bookingRequirements` to decide which fields the traveller and contact forms must collect:

```tsx
// app/flights/review/[pricedOfferId]/page.tsx
const priced = await velexisServer().flights.getPricedOffer({ pricedOfferId });
const req = priced.bookingRequirements;
// req.emailAddressRequired, req.mobilePhoneNumberRequired, req.phoneCountryCodeRequired, req.postalCodeRequired …
// req.travelerRequirements: [{ travelerId: "1", dateOfBirthRequired, genderRequired, documentRequired,
//   documentIssuanceCityRequired, redressRequiredIfAny, residenceRequired, spanishResidentDiscountRequired, airFranceDiscountRequired }]
// priced.offers[0].travelerPricings → traveller ids and types for the forms
// priced.creditCardFees → "+ €12.50 with VISA" next to the card brands (pass payments:[{brand}] to get them)
// priced.conditions → refundable / changeable badges; priced.expiresAt → countdown
// → open the checkout with priced.id (checkout namespace)
```

Credit-card fees depend on the card. Send the brand (and optionally the first 6 digits) once the user picks a card. Re-price with `payments: [{ brand: "VISA", bin: "411111" }]` and `include: ["credit-card-fees"]`. Velexis sends `bin` to Amadeus as `binNumber`. The checkout's card hint uses the same names (`brand`, `bin`). The fee is **not** part of `price.total`.

## 6. Extras (bags, services, seats) and fare rules

```tsx
// app/flights/review/[pricedOfferId]/extras.tsx (server component part)
const vx = velexisServer();
const catalogue = priced.ancillaryCatalogue ?? (await vx.flights.getAncillaries({ pricedOfferId: priced.id }));
// catalogue.checkedBags / cabinBags / otherServices / seats: AncillaryOption[]
//   option.travelerIds, option.segmentIds, option.quantity, option.weight, option.price (selling)
//   option.amadeus.additionalServices → the exact Amadeus item (e.g. { chargeableCheckedBags: { quantity: 1, weight: 23, weightUnit: "KG" } })
// catalogue.seatsSupported → render a seat-number input only when true (no seat maps in this API set)
```

**Seats: known limitation.** The supplier scope has no seat map (Amadeus SeatMap Display is not one of the integrated APIs). Velexis therefore cannot list seats, their availability or their characteristics (window, aisle, legroom). A SEATS option (`requiresSeatNumber: true`, `price: null`) only tells you that the offer sells chargeable seats. Ask for a seat number (free text, e.g. `14C`, pattern `^[1-9][0-9]{0,2}[A-Z]?$`) and re-price with `{ optionId, travelerId, seatNumber }`. The airline validates the number at that point:

- unknown seat: `ANCILLARY_NOT_AVAILABLE` with `details.reason: "seat_unknown"`
- occupied or blocked seat: `details.reason: "seat_unavailable"`

Both errors also carry `details.seatNumber`, `details.segmentId` and `details.selectionIndex`. The seat price is known only after that re-pricing. Phrase the input as a *request* ("preferred seat"), not a seat picker. A seat-map method (`flights.getSeatMap`) is planned for when SeatMap Display joins the supplier scope.

```ts
// server action: re-price with the chosen extras → a NEW priced offer whose total includes them
"use server";
export async function addExtras(offerIds: string[], picks: { optionId: string; travelerId: string; quantity?: number }[], shownTotal: Money) {
  const priced = await velexisServer().flights.price({
    offerIds,
    include: ["bags", "other-services"],
    additionalServices: picks,  // or explicit: { type: "OTHER_SERVICES", serviceName: "PRIORITY_BOARDING", travelerId: "1", segmentIds: ["1"] }
    expectedTotal: shownTotal,  // base total + catalogue prices of the picks
  });
  return priced.id;             // priced.selectedAncillaries, priced.price.additionalServices
}
```

`ANCILLARY_NOT_AVAILABLE` (422) has `details.selectionIndex` and `details.reason` (`unknown_option`, `not_bookable_for_traveler`, `not_bookable_for_segment`, `quantity_exceeded`, `rejected_by_airline`, `seat_unknown`, `seat_unavailable`). Show it next to the offending pick.

Fare rules for a "Conditions" drawer:

```tsx
const rules = priced.fareRules ?? (await velexis.flights.getFareRules({ pricedOfferId }));
// rules.summary: { refundable, changeable, refundPenalty, changePenalty, source }
// rules.categories: REFUND / EXCHANGE / … with applicable, chargeable, maxPenalty, texts
// rules.fareComponents: detailed notes per fare basis; rules.raw: verbatim Amadeus fareRules + detailed-fare-rules
```

## 7. Console

- **Console scope** comes from a staff token, or from a secret key without customer token plus `X-Velexis-Scope: console` (console backends, reporting jobs). A secret key on its own gets the customer view, like a storefront.
- **Expert search**: use `flights.search({ mode: "advanced", query })` in console scope. Every Amadeus option is available, including corporate codes, negotiated fare types and `connectionRestriction.nonStopPreferred` / `nonStopPreferredWeight`. The response includes `diagnostics`, and offers include `netPrice` and `markup`.
- **Raw pricing**: `flights.price({ amadeusFlightOffers: [...] })` prices Amadeus offers that came from outside Velexis. This needs console scope.
- **Availability screen**: server-only, using a secret key or a staff token with role owner, admin or agent. The operation is console-only, so it needs no scope header. `query` is exactly the Amadeus Flight Availabilities Search body: sources `GDS`, `LTC`, `PYTON`, `EAC`. Search-only fields (location subtypes, `fareOptions`, `NDC`, `nonStopPreferred`) are rejected with `400`. Each search is recorded in `flight_searches` (`kind = availability`) and its id comes back as `searchId` for audit.

```ts
// console backend without a staff session (e.g. a nightly margin report): opt in to the console view
const consoleVx = createVelexisClient({ secretKey: process.env.VELEXIS_SECRET_KEY!, headers: { "X-Velexis-Scope": "console" } });
const offer = await consoleVx.flights.getOffer({ offerId }); // offer.netPrice, offer.markup, verbatim offer.amadeus
```

```ts
// app/console/availability/actions.ts
"use server";
import { velexisServer } from "@/lib/velexis";

export async function availability(staffToken: string, from: string, to: string, date: string) {
  return velexisServer().flights.availability(
    {
      query: {
        originDestinations: [{ id: "1", originLocationCode: from, destinationLocationCode: to, departureDateTime: { date } }],
```

## 8. Error handling cheat-sheet

| Code (HTTP) | SDK class | Thrown by | What to do |
|---|---|---|---|
| `VALIDATION_FAILED`, `INVALID_REQUEST` (400) | `ValidationError` | all | Show `fieldErrors`. For `listResults`, drop a stale cursor. |
| `UNPROCESSABLE` (422) | `ValidationError` | search, price, availability | Business rule failed, e.g. past date or more infants than adults |
| `OFFER_COMBINATION_INVALID` (422) | `ValidationError` | upsell, price | Offers come from different searches or cannot be combined |
| `ANCILLARY_NOT_AVAILABLE` (422) | `ValidationError` | price | Remove or adjust `additionalServices[details.selectionIndex]`. For `seat_unknown` / `seat_unavailable`, ask for another seat number. |
| `TRAVELER_DATA_INVALID` (422) | `ValidationError` | price | Fix `travelers` (discount or loyalty data) |
| `FEATURE_DISABLED`, `SCOPE_NOT_ALLOWED` (403) | `PermissionError` | search, upsell, availability, getAncillaries, price; any shopping call with `X-Velexis-Scope: console` from a publishable key or customer token | Hide the feature, or call with a staff token (console scope) |
| `NOT_FOUND` (404) | `NotFoundError` | reads | Unknown id, or the resource belongs to another customer (a plain secret key without that customer's token gets `404` too) |
| `PRICE_CHANGED` (409) | `PriceChangedError` | price (with `expectedTotal`) | Show `e.oldPrice` → `e.newPrice`. Continue with `e.pricedOfferId`. |
| `SEARCH_NOT_COMPLETED` (409) | `ConflictError` | listResults | Async search still `pending` (wait `details.retryAfterSeconds`, poll `getSearch`) or `failed` (search again) |
| `IDEMPOTENCY_KEY_REUSED`, `CONFLICT` (409) | `ConflictError` | search, upsell, availability, price | The same `idempotencyKey` was sent with another body, or the first attempt is still running. Let the SDK generate keys. |
| `SOLD_OUT` (409) | `SoldOutError` | upsell, price | Return to results |
| `SEARCH_EXPIRED` (410) | `ExpiredError` | listResults | Re-run `search` with `getSearch().criteria.request` |
| `OFFER_EXPIRED` (410) | `ExpiredError` | getOffer, upsell, price, priced-offer reads | Price again, or search again |
| `RATE_LIMITED` (429) | `RateLimitError` | all | Retried automatically. Back off using `retryAfterSeconds`. |
| `SUPPLIER_NOT_CONFIGURED` (424) | `SupplierError` | Amadeus-backed calls | The OTA has no Amadeus connection for this environment |
| `SUPPLIER_ERROR` (502), `SUPPLIER_UNAVAILABLE` (503), `SUPPLIER_TIMEOUT` (504) | `SupplierError` | Amadeus-backed calls | Show "try again". Console users see `error.supplier`. |

## 9. Mapping: SDK → HTTP → Amadeus → tenant tables

| SDK method | HTTP route | Amadeus operation | Tenant tables | Scope |
|---|---|---|---|---|
| `flights.search` | `POST /v1/flight-searches` (`201` sync, `202` async) | FlightOffersSearch `getFlightOffers` (GET /v2/shopping/flight-offers, simple mode) and `searchFlightOffers` (POST /v2/shopping/flight-offers, advanced mode) | flight_searches, flight_offers, markup_rules, fee_rules, storefront_settings, supplier_requests, idempotency_keys | both |
| `flights.getSearch` | `GET /v1/flight-searches/{searchId}` | none | flight_searches | both |
| `flights.listResults` | `GET /v1/flight-searches/{searchId}/offers` | none | flight_searches, flight_offers | both |
| `flights.getOffer` | `GET /v1/flight-offers/{offerId}` | none | flight_offers, flight_searches | both |
| `flights.upsell` | `POST /v1/flight-offers/{offerId}/upsells` | BrandedFaresUpsell `upsellAirOffers` (POST /v1/shopping/flight-offers/upselling) | flight_offers, offer_upsells, flight_searches, markup_rules, fee_rules, storefront_settings, supplier_requests, idempotency_keys | both |
| `flights.availability` | `POST /v1/flight-availabilities` | FlightAvailabilitiesSearch `searchFlightAvailabilities` (POST /v1/shopping/availability/flight-availabilities) | flight_searches (`kind = availability`), supplier_requests, idempotency_keys | console |
| `flights.price` | `POST /v1/priced-offers` | FlightOffersPrice `quoteAirOffers` (POST /v1/shopping/flight-offers/pricing, `include`, `forceClass`) | flight_offers, priced_offers, flight_searches, markup_rules, fee_rules, storefront_settings, supplier_requests, idempotency_keys | both |
| `flights.getPricedOffer` | `GET /v1/priced-offers/{pricedOfferId}` | none | priced_offers | both |
| `flights.getAncillaries` | `GET /v1/priced-offers/{pricedOfferId}/ancillaries` | FlightOffersPrice `quoteAirOffers` (`include=bags,other-services`, only if not loaded yet) | priced_offers, flight_offers, markup_rules, storefront_settings, supplier_requests | both |
| `flights.getFareRules` | `GET /v1/priced-offers/{pricedOfferId}/fare-rules` | FlightOffersPrice `quoteAirOffers` (`include=detailed-fare-rules`, only if not loaded yet) | priced_offers, flight_offers, supplier_requests | both |

How NestJS fills Amadeus fields that the client does not send:

- **currency**: `currencyCode`, then `X-Currency`, then the storefront default.
- **sources**: intersected with the sources enabled on the tenant's Amadeus connection (`platform.supplier_connections`).
- **maxFlightOffers / max**: capped by the storefront limit.
- **additionalInformation**: flags default to `true`.
- **pricing `include`**: defaults from storefront settings.
- **markup**: from `markup_rules`, folded into the base fare. Customer scope (publishable keys and secret keys, with or without a customer token) receives selling amounts, including inside `amadeus`. Console scope (staff token, or secret key with `X-Velexis-Scope: console`) receives net amounts, `netPrice` and `markup`.
- **service fees**: from `fee_rules`.
- **ancillary markup**: from `markup_rules` with scope `ancillary`.
