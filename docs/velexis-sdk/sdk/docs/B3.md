# Checkout, payment and bookings with `velexis.checkout` and `velexis.bookings` (Next.js App Router)

This guide covers everything after the price is confirmed. You start from a priced offer (`prc_…` from `flights.price`, see the B2 guide) and end with a booking the customer can manage.

| Step | SDK method | Result |
|---|---|---|
| Open the checkout | `checkout.create` | `Checkout` (`chk_…`) with `requirements`, `progress`, `totals` |
| Travellers | `checkout.setTravelers` | travellers validated against the airline's booking requirements |
| Booking contacts | `checkout.setContacts` | primary contact (+ invoice contact) |
| Extras | `checkout.setAncillaries` | bags, services and seats re-priced with Amadeus |
| Special requests | `checkout.setRemarks` | Amadeus general remarks for the OTA's staff |
| Payment | `checkout.createPayment`, `checkout.updatePayment`, `checkout.getPayment` | `Payment` (`pay_…`) with `clientSecret` for the provider SDK; card fee re-quoted for the card actually entered |
| Book and ticket | `checkout.complete` | `CheckoutCompletion`: `Booking` (`bkg_…`) + guest `bookingToken` |
| Confirmation | `bookings.getTicketingStatus` | booking status and ticket numbers once issued |
| My trips | `bookings.list` | `Page<BookingSummary>` (`timeframe`: upcoming / past / cancelled) |
| Manage booking | `bookings.lookup`, `bookings.get`, `bookings.update`, `bookings.getFareRules` | guest access, detail, changes, conditions |
| Extra bags after booking | `bookings.getAncillaries`, `bookings.createPayment`, `bookings.addAncillaries` | priced bag options, payment, bags added to the Amadeus order |
| Cancel | `bookings.quoteCancellation`, `bookings.cancel` | refund preview, cancellation + refund |
| Documents & timeline | `bookings.listDocuments`, `bookings.getDocumentDownloadUrl`, `bookings.listEvents` | e-tickets, itinerary, invoices, history |

Staff work on bookings (issuing tickets, raw Amadeus PATCH, importing PNRs, queues, seats and services after booking) is in the `console` namespace, not here.

## 1. Keys, tokens and where to call what

| Caller | Client | Key | Token | Use for |
|---|---|---|---|---|
| Client component | `createBrowserClient()` | publishable `pk_…` (direct) / same-origin proxy | httpOnly cookies, attached by the proxy | extras picker, payment form, ticketing polling |
| Server component, server action, route handler | `createServerClient()` / `createServerClient({ bookingId })` | secret `sk_…` | customer session cookies (`vx_at` / `vx_rt`, refreshed automatically) **or** the guest cookie `vx_bt_<bookingId>` | every method; recommended for travellers, completion, lookup, update, extras, cancel |
| Console | `createServerClient({ as: "staff" })` | secret `sk_…` | staff token | assisted checkout (`channel: "console"`) |

- **Customers** own their checkouts and bookings. `bookings.list` requires a customer token.
- **Guests** check out with only the key, if the storefront allows guest checkout. Guest checkouts are capability URLs: anyone with the `chk_…` id and your key can read them. Because of this, documents carry only `numberMasked` and payment secrets are omitted.
- **Guest bookings** need an `X-Booking-Token`. You get one from `checkout.complete` (shown once — also in the `SUPPLIER_TIMEOUT` error details) or from `bookings.lookup` (booking reference + last name). Store it with `setBookingTokenCookie()` in the httpOnly cookie `vx_bt_<bookingId>` and read it server-side with `createServerClient({ bookingId })`. **Never pass the token to a client component** (no props, no localStorage): client-side calls go through the browser client's same-origin proxy, which attaches the cookie. The token gives access to that one booking only.
- **Test and live are separate.** A `pk_test_`/`sk_test_` key sees only test checkouts, payments and bookings; a live key only live ones. Customers are shared by both, so the same customer may have test bookings — they never appear with a live key (anything of the other environment is a `404`).
- **Ids.** `travelerId` is always the Amadeus traveller id (`"1"`, `"2"`, …) — in `setTravelers`, `bookings.update`, remarks and extras, and in every response. `Traveler.id` (`ctr_…` / `btr_…`) is the Velexis row id and is never sent back. Saved travellers from the account are `trv_…` (`savedTravelerId`).
- Everything here is personal or priced, so the SDK sends `cache: "no-store"`. Never use `next.revalidate` with these methods. After a change, call `revalidatePath` for the pages that show the booking.
- The SDK adds an `Idempotency-Key` to every state-changing POST (`create`, `createPayment`, `complete`, `lookup`, `cancel`, `bookings.createPayment`, `bookings.addAncillaries`). For `complete`, `addAncillaries` and `cancel`, pass your own **stable** key. A repeated key always replays the stored outcome — even after `504 SUPPLIER_TIMEOUT`, where a same-key retry never calls Amadeus again — so the SDK's automatic retries are safe for these calls.
- `If-Match`: checkout steps accept an optional `ifMatch` (`checkout.version`). `bookings.update`, `bookings.addAncillaries` and `bookings.cancel` **require** it. Pass `booking.version`; the SDK sends it as `"<version>"`.

The examples use the ready-made helpers of `@velexis/ota-sdk/next` (same cookie names — `vx_at`, `vx_rt`, `vx_bt_<bookingId>` — and environment variables — `VELEXIS_SECRET_KEY`, `NEXT_PUBLIC_VELEXIS_PUBLISHABLE_KEY` — as the B1 auth handlers, with automatic token refresh):

```ts
// lib/velexis.ts — server only
import "server-only";
import { createServerClient } from "@velexis/ota-sdk/next";

/** Customer session (vx_at / vx_rt, refreshed automatically) — or anonymous for guests. */
export const customerClient = () => createServerClient();
/** Customer session, else the guest token of this booking (cookie vx_bt_<bookingId>). */
export const bookingClient = (bookingId: string) => createServerClient({ bookingId });

// lib/velexis-browser.ts — client components
"use client";
import { createBrowserClient } from "@velexis/ota-sdk/next";
// NEXT_PUBLIC_VELEXIS_PUBLISHABLE_KEY; token-bound calls go through the /api/velexis proxy (httpOnly cookies).
export const velexis = createBrowserClient();
```

## 2. Checkout flow

### 2.1 Open the checkout (server action from the review page)

```ts
// app/flights/review/[pricedOfferId]/actions.ts
"use server";
import { redirect } from "next/navigation";
import { isVelexisError } from "@velexis/ota-sdk";
import { customerClient } from "@/lib/velexis";

export async function startCheckout(pricedOfferId: string) {
  let checkoutId: string;
  try {
    checkoutId = (await (await customerClient()).checkout.create({ pricedOfferId })).id;
  } catch (e) {
    if (isVelexisError(e, "OFFER_EXPIRED")) redirect(`/flights/review/${pricedOfferId}?expired=1`); // price again
    if (isVelexisError(e, "UNAUTHENTICATED")) redirect(`/sign-in?next=/flights/review/${pricedOfferId}`); // guest checkout disabled
    if (isVelexisError(e, "EMAIL_NOT_VERIFIED")) redirect(`/account/verify-email?next=/flights/review/${pricedOfferId}`);
    throw e;
  }
  redirect(`/checkout/${checkoutId}/travellers`);
}
```

The new checkout has one empty traveller per Amadeus traveller (`travelerId` `"1"`, `"2"`, …). It also has `requirements` built from the airline's booking requirements:

- `requirements.travelers[i].requiredFields`: `name`, `dateOfBirth`, `gender`, `documents`, `documentIssuanceCity`, `redress`, `residence`, `airFranceDiscount`, `spanishResidentDiscount`.
- `dateOfBirthMin` / `dateOfBirthMax`: the valid range for the traveller type at the travel dates. Use it to limit date pickers.
- `associatedAdultId` (held infants): the `travelerId` of the adult carrying the infant.
- `documentTypes`: `PASSPORT` for international trips; `PASSPORT` or `IDENTITY_CARD` inside the Schengen area.
- `requirements.contact`: e-mail, mobile phone, country calling code, invoice / postal address flags.

### 2.2 Travellers (server component + server action)

```tsx
// app/checkout/[checkoutId]/travellers/page.tsx
import { redirect } from "next/navigation";
import { customerClient } from "@/lib/velexis";
import { TravellerForm } from "./traveller-form";

export default async function TravellersPage({ params }: { params: Promise<{ checkoutId: string }> }) {
  const { checkoutId } = await params;
  const checkout = await (await customerClient()).checkout.get({ checkoutId });
  if (checkout.status === "completed") redirect(`/trips/${checkout.bookingId}`);
  if (checkout.status === "expired") redirect(`/checkout/${checkoutId}/expired`);
  return checkout.requirements.travelers.map((req) => (
    <TravellerForm key={req.travelerId} checkoutId={checkoutId} version={checkout.version}
      requirement={req} traveler={checkout.travelers.find((t) => t.travelerId === req.travelerId)!} />
  ));
}
```

```ts
// app/checkout/[checkoutId]/travellers/actions.ts
"use server";
import { isVelexisError, type TravelerInput } from "@velexis/ota-sdk";
import { customerClient } from "@/lib/velexis";

export async function saveTraveller(checkoutId: string, input: TravelerInput) {
  try {
    // input.travelerId = the form's traveler.travelerId ("1", "2", …) — never traveler.id (ctr_…)
    const checkout = await (await customerClient()).checkout.setTravelers({ checkoutId, travelers: [input] });
    return { ok: true as const, progress: checkout.progress };
  } catch (e) {
    // 422 TRAVELER_DATA_INVALID: fieldErrors[].path = "/travelers/0/documents/0/expiryDate", code = "DOCUMENT_EXPIRES_BEFORE_RETURN"
    if (isVelexisError(e, "TRAVELER_DATA_INVALID") || isVelexisError(e, "VALIDATION_FAILED")) {
      return { ok: false as const, fieldErrors: e.fieldErrors };
    }
    if (isVelexisError(e, "CHECKOUT_EXPIRED")) return { ok: false as const, expired: true };
    throw e;
  }
}
```

Traveller inputs follow the Amadeus `Traveler` shape, keyed by `travelerId`: `name` (`firstName`, `middleName`, `lastName`, `secondLastName`), `dateOfBirth`, `gender`, `contact` (`emailAddress`, `phones[]` with `deviceType`, `countryCallingCode`, `number`), `documents[]` (`documentType`, `number`, `issuanceDate`, `expiryDate`, `issuanceCountry`, `issuanceLocation`, `nationality`, `birthPlace`, `validityCountry`, `birthCountry`, `holder`), `loyaltyPrograms[]`, `discountEligibility[]` and `emergencyContact`. Response-only fields (`id`, `travelerType`, `complete`, `missingFields`, `ticketNumbers`) are not accepted.

**Document numbers.** Responses never contain a document number: `checkout.travelers[i].documents[j].numberMasked` holds `"•••••4821"` (the same field name as saved travellers in B1). When you send documents back, a document **without** `number` keeps the stored number of the document with the same `documentType` + `issuanceCountry`; a masked value is rejected with `400 VALIDATION_FAILED`, so it can never reach the airline. So a form that edits only the expiry date can send the response document back with the new date.

Signed-in customers can send `{ travelerId: "1", savedTravelerId: "trv_…" }` to copy a saved traveller. Explicit fields override the copy. Add `saveToAccount: true` to save new data after the booking. Each listed traveller is replaced and the others are kept, so you can save one traveller form at a time.

### 2.4 Extras (client component, re-priced with Amadeus)

Load the options with `flights.getAncillaries({ pricedOfferId: checkout.basePricedOfferId })` (B2), then:

```tsx
"use client";
import { PriceChangedError, isVelexisError, type Checkout } from "@velexis/ota-sdk";
import { velexis } from "@/lib/velexis-browser";

async function applyExtras(checkout: Checkout, selections: { optionId: string; travelerId: string; quantity?: number }[], shownTotal: string) {
  try {
    return await velexis.checkout.setAncillaries({
      checkoutId: checkout.id, ifMatch: checkout.version, selections,
      expectedTotal: { amount: shownTotal, currency: checkout.currency },
    });
  } catch (e) {
    if (e instanceof PriceChangedError) {
      // checkout unchanged; e.newPrice is the re-priced total — show it, then call again with expectedTotal = e.newPrice
      throw new Error(`New total ${e.newPrice?.amount} ${e.newPrice?.currency}`);
    }
    if (isVelexisError(e, "ANCILLARY_NOT_AVAILABLE")) {
      // e.details.selectionIndex / e.details.reason (rejected_by_airline, quantity_exceeded, …)
    }
    throw e;
  }
}
```

Velexis calls Flight Offers Price with the selections in `fareDetailsBySegment[].additionalServices` and stores a new priced offer (`checkout.pricedOfferId`). If the payment is not confirmed yet, its amount is updated at the provider. If it was already authorised, it is voided and you must create a new payment. `selections: []` removes all extras.

### 2.5 Special requests (optional)

```ts
await velexis.checkout.setRemarks({ checkoutId, remarks: [{ text: "Child meal requested for Leo if possible", travelerIds: ["2"] }] });
```

Requests become Amadeus general remarks (`GENERAL_MISCELLANEOUS`). The OTA's staff read them in the console. They are not sent to the airline automatically.

### 2.6 Payment (client component with the provider SDK)

`createPayment` needs complete travellers and contacts (`422 CHECKOUT_INCOMPLETE` otherwise) and `termsAccepted: true`. You do **not** need the card brand up front: provider card forms report the brand / BIN only after the customer typed the card, which is after the payment (and its `clientSecret`) must exist. Create the payment without `card`, then call `checkout.updatePayment` from the form's brand event. Velexis re-quotes the credit-card fee for that brand (Amadeus credit-card fees + OTA surcharge) and updates the amount of the **same** provider payment — no second payment, no orphaned provider intent.

```tsx
"use client";
import type { PaymentCardHint, Payment } from "@velexis/ota-sdk";
import { velexis } from "@/lib/velexis-browser";
import { completeCheckout } from "../actions";

// 1. When the payment step opens
export async function startPayment(checkoutId: string) {
  return velexis.checkout.createPayment({
    checkoutId, method: "card", termsAccepted: true,
    returnUrl: `${window.location.origin}/checkout/${checkoutId}/return`,
  }); // mount the provider form with payment.clientSecret / payment.providerPublicKey
}

// 2. From the provider form's brand / BIN event (Adyen onBinLookup, Checkout.com Frames cardBinChanged,
//    Stripe confirmation token payment_method_preview.card)
export async function onCardBrand(payment: Payment, brand: PaymentCardHint["brand"], bin?: string) {
  const updated = await velexis.checkout.updatePayment({ paymentId: payment.id, card: bin ? { brand, bin } : { brand } });
  return updated.amount; // includes updated.cardFee (also checkout.totals.cardFee): show it before the customer confirms
}

// 3. After the provider SDK confirmed the card (3-D Secure happens there)
export async function finishPayment(checkoutId: string, payment: Payment) {
  let p = await velexis.checkout.getPayment({ paymentId: payment.id });
  while (p.status === "processing" || p.status === "requires_action") {
    await new Promise((r) => setTimeout(r, 2000));
    p = await velexis.checkout.getPayment({ paymentId: payment.id });
  }
  if (p.status !== "authorized" && p.status !== "captured") throw new Error(p.failure?.message ?? "Payment failed"); // failed / cancelled
  return completeCheckout(checkoutId, p.id, p.amount);
}
```

`updatePayment` works only while the payment is `requires_payment_method`; after confirmation started it throws `PAYMENT_NOT_UPDATABLE` (409) — create a new payment. A fare change found while quoting the fee throws `PRICE_CHANGED`: the checkout moved to the new price and the payment was cancelled; show the new total and create a new payment.

For redirect flows (`nextAction.type === "redirect"`, PayPal), send the browser to `payment.redirectUrl`. On the `returnUrl` page (a server component), call `checkout.getPayment` and then `completeCheckout`.

Velexis never sees card data. By default, payments are authorised only (`captureMethod: "manual"`) and captured after the Amadeus order exists, so a failed booking never leaves a charge behind.

**Money fields.** `checkout.totals.total = offer + ancillaries + cardFee`. Supplier and OTA service fees are part of `offer` (they are `fees` in the priced offer's `SellingPrice` and in `booking.totals.fees`); the credit-card fee is always the separate `cardFee` (`checkout.totals.cardFee`, `payment.cardFee`, `booking.totals.cardFee`).

### 2.7 Complete (server action — books and tickets)

```ts
// app/checkout/[checkoutId]/actions.ts
"use server";
import { redirect } from "next/navigation";
import { isVelexisError, type CheckoutTimeoutDetails, type Money } from "@velexis/ota-sdk";
import { setBookingTokenCookie } from "@velexis/ota-sdk/next";
import { customerClient } from "@/lib/velexis";

export async function completeCheckout(checkoutId: string, paymentId: string, expectedTotal: Money) {
  let target: string;
  try {
    const done = await (await customerClient()).checkout.complete(
      { checkoutId, paymentId, expectedTotal },
      { idempotencyKey: `complete-${checkoutId}-${paymentId}`, timeoutMs: 90_000 }, // stable key: a retry replays, never re-books
    );
    if (done.bookingToken) await setBookingTokenCookie(done.booking.id, done.bookingToken, done.bookingTokenExpiresAt); // httpOnly vx_bt_<id>
    target = `/trips/${done.booking.id}?new=1`;
  } catch (e) {
    if (isVelexisError(e, "SUPPLIER_TIMEOUT")) {
      // The order may exist: never book again with a new key. A pending booking exists — keep its token and poll it.
      const { bookingId, bookingToken, bookingTokenExpiresAt } = e.details as unknown as CheckoutTimeoutDetails;
      if (bookingToken) await setBookingTokenCookie(bookingId, bookingToken, bookingTokenExpiresAt);
      target = `/trips/${bookingId}?pending=1`;
    } else if (isVelexisError(e, "PRICE_CHANGED")) {
      return { priceChanged: e.details }; // authorisation voided, checkout moved to the new price → show it, create a new payment
    } else if (isVelexisError(e, "SOLD_OUT")) {
      return { soldOut: true };           // payment voided; send the customer back to the results
    } else if (isVelexisError(e, "PAYMENT_REQUIRED") || isVelexisError(e, "PAYMENT_DECLINED")) {
      return { paymentProblem: e.code };
    } else if (isVelexisError(e, "CHECKOUT_ALREADY_COMPLETED")) {
      target = `/trips/${String(e.details?.bookingId)}`;
    } else {
      throw e;
    }
  }
  redirect(target);
}
```

`complete` does the following:

1. Checks that the payment is authorised for exactly `totals.total`.
2. Re-prices with Flight Offers Price if the price is older than about 10 minutes (or travellers carry discount data).
3. Creates the Amadeus order with Flight Create Orders. The request carries the travellers, contacts, remarks, and the OTA's ticketing agreement, automated process, queuing office and form of payment.
4. Captures the payment.
5. Issues tickets, depending on `checkout.ticketing.policy`:
   - `issue_at_booking`: `issue=true` on create-order.
   - `issue_after_payment`: Flight Order Issue after capture.
   - `manual_review`: staff issue the tickets.

If ticketing fails, the call still succeeds. The booking comes back `confirmed` with `ticketing.status = "failed"`, and Velexis retries until the deadline.

**Timeouts and retries.** Velexis calls Flight Create Orders at most once per checkout. A request with an idempotency key it has already seen replays the stored outcome: the `201`, the final error, or — after a `504 SUPPLIER_TIMEOUT` — the same 504 with the same `details` (`replayed: true`) until the reconciliation job (up to 15 minutes) has found or ruled out the order, then the final result. That is why the SDK may retry this call automatically, and why a replayed 504 returns immediately. What you must never do is call `complete` again with a **new** key after a 504: poll the booking instead (2.8).

### 2.8 Confirmation page (poll ticketing)

```tsx
"use client";
import { useEffect, useState } from "react";
import type { BookingTicketingStatus } from "@velexis/ota-sdk";
import { velexis } from "@/lib/velexis-browser"; // the proxy attaches the session or vx_bt_<bookingId> — no token in props

export function TicketingBadge({ bookingId }: { bookingId: string }) {
  const [s, setS] = useState<BookingTicketingStatus>();
  useEffect(() => {
    let stop = false;
    (async function poll() {
      const next = await velexis.bookings.getTicketingStatus({ bookingId, refresh: true });
      if (stop) return;
      setS(next);
      if (next.pollAfterSeconds) setTimeout(poll, next.pollAfterSeconds * 1000);
    })();
    return () => { stop = true; };
  }, [bookingId]);
  if (!s) return null;
  if (s.bookingStatus === "pending") return <p>{s.message}</p>;          // outcome still unknown after a timeout
  if (s.bookingStatus === "failed") return <p>Your booking did not go through ({s.failureCode}). You have not been charged.</p>;
  return <p>{s.message} {s.tickets.map((t) => t.documentNumber).join(", ")}</p>;
}
```

`@velexis/ota-sdk/react` offers the same as `useTicketingStatus(bookingId)`. After a `SUPPLIER_TIMEOUT`, poll until `bookingStatus` (always present) leaves `pending`; while it is pending, `status` is `pending`, `pollAfterSeconds` is 10 and `refresh` has no effect (there is no Amadeus order id yet). The final state is `confirmed` / `ticketed` (then follow `status`) or `failed`.

## 3. My trips (customer)

```tsx
// app/trips/page.tsx
import Link from "next/link";
import { customerClient } from "@/lib/velexis";

export default async function Trips({ searchParams }: { searchParams: Promise<{ tab?: "upcoming" | "past" | "cancelled"; cursor?: string }> }) {
  const { tab = "upcoming", cursor } = await searchParams;
  const page = await (await customerClient()).bookings.list({ timeframe: tab, cursor, limit: 20 });
  return (
    <>
      {page.data.map((b) => (
        <Link key={b.id} href={`/trips/${b.id}`}>
          {b.reference} · {b.originCode}→{b.destinationCode} · {b.departureAt.slice(0, 10)} · {b.ticketingStatus}
          {b.hasScheduleChange && " · schedule changed"}
        </Link>
      ))}
      {page.page.nextCursor && <Link href={`/trips?tab=${tab}&cursor=${page.page.nextCursor}`}>More</Link>}
    </>
  );
}
```

The filter is `timeframe` (it matches `BookingSummary.timeframe`; it is not a booking status — the console list filters by `BookingStatus`):

- `upcoming`: the last flight has not landed.
- `past`: the last flight has landed.
- `cancelled`: cancelled bookings.
- `all`: every booking except `failed`; customers never see `failed` bookings in lists.

`createdFrom` (inclusive) and `createdTo` (exclusive) are ISO-8601 date-times, exactly like the console lists; for one whole day pass the next midnight as `createdTo`. Only bookings of your key's environment are listed. The list comes from tenant tables. A background job refreshes upcoming bookings from Amadeus every 6 h.

## 4. Manage booking (customer or guest)

### 4.1 Guest lookup (server action)

```ts
"use server";
import { redirect } from "next/navigation";
import { isVelexisError } from "@velexis/ota-sdk";
import { createServerClient, setBookingTokenCookie } from "@velexis/ota-sdk/next";

export async function findBooking(_: unknown, form: FormData) {
  let bookingId: string;
  try {
    const vx = await createServerClient({ as: "anonymous" });
    const r = await vx.bookings.lookup({ bookingReference: String(form.get("ref")), lastName: String(form.get("lastName")) });
    await setBookingTokenCookie(r.bookingId, r.bookingToken, r.expiresAt); // httpOnly vx_bt_<bookingId>
    bookingId = r.bookingId;
  } catch (e) {
    if (isVelexisError(e, "NOT_FOUND")) return { error: "We could not find a booking with this reference and last name." };
    if (isVelexisError(e, "RATE_LIMITED")) return { error: "Too many attempts, try again later." };
    throw e;
  }
  redirect(`/trips/${bookingId}`);
}
```

### 4.2 Booking page (server component, optional live refresh)

```tsx
// app/trips/[bookingId]/page.tsx
import { bookingClient } from "@/lib/velexis";

export default async function BookingPage({ params, searchParams }: { params: Promise<{ bookingId: string }>; searchParams: Promise<{ refresh?: string }> }) {
  const { bookingId } = await params;
  const { refresh } = await searchParams;
  const vx = await bookingClient(bookingId); // customer session, else the guest cookie vx_bt_<bookingId>
  const booking = await vx.bookings.get({ bookingId, refresh: refresh === "1", fareRules: ["rebooks", "refunds"] });
  return <BookingDetail booking={booking} />; // booking.allowedActions drives the buttons; booking.version is the If-Match value
}
```

`refresh: true` calls Flight Order Management GET (at most once per 60 s per booking; otherwise `syncStatus: "throttled"`). It picks up schedule changes, new tickets and airline record locators (`recordLocators` with the airline's `originSystemCode`, which is what online check-in needs).

The booking never contains a full identity-document number, also not in the wrapped Amadeus order: `booking.travelers[].documents[].numberMasked`, and `booking.amadeus.order.travelers[].documents[].number` / `discountEligibility[].cardNumber` hold masked values in customer scope. This matters because a guest token only needs a reference and a last name.

### 4.3 Update documents, contacts, loyalty, requests

```ts
"use server";
import { revalidatePath } from "next/cache";
import { isVelexisError, type BookingTravelerUpdate, type TravelerDocument } from "@velexis/ota-sdk";
import { bookingClient } from "@/lib/velexis";

/** New passport for traveller "2" (replaces that traveller's documents). */
export async function renewPassport(bookingId: string, version: number) {
  return save(bookingId, version, [{ travelerId: "2", documents: [{ documentType: "PASSPORT", number: "AC1102299",
    issuanceDate: "2026-10-01", expiryDate: "2031-10-01", issuanceCountry: "SE", nationality: "SE", holder: true }] }]);
}

/** Correct only the expiry date: send the stored documents back; entries without `number` keep the stored number. */
export async function fixExpiry(bookingId: string, version: number, travelerId: string, docs: TravelerDocument[], expiryDate: string) {
  return save(bookingId, version, [{ travelerId, documents: docs.map((d) => (d.documentType === "PASSPORT" ? { ...d, expiryDate } : d)) }]);
}

async function save(bookingId: string, version: number, travelers: BookingTravelerUpdate[]) {
  try {
    await (await bookingClient(bookingId)).bookings.update({ bookingId, ifMatch: version, travelers });
  } catch (e) {
    if (isVelexisError(e, "PRECONDITION_FAILED") || isVelexisError(e, "VERSION_CONFLICT")) return { reload: true }; // someone else changed it
    if (isVelexisError(e, "BOOKING_NOT_MODIFIABLE")) return { notAllowed: e.details };
    if (isVelexisError(e, "TRAVELER_DATA_INVALID")) return { fieldErrors: e.fieldErrors };
    throw e;
  }
  revalidatePath(`/trips/${bookingId}`);
}
```

Customers can change: contacts (the whole list is replaced), traveller identity/APIS documents, traveller contact, emergency contact, loyalty numbers, and they can add special requests. Travellers are addressed by `travelerId` (`booking.travelers[i].travelerId`), never by `id` (`btr_…`). Names, dates of birth and gender cannot be changed.

### 4.4 Extra bags after booking

When `booking.allowedActions.canAddAncillaries` is true, the customer can still buy extra checked bags. Amadeus prices only bags on an existing order; seats and other services after booking are handled by the OTA's staff.

```tsx
// app/trips/[bookingId]/extras/page.tsx (server component)
import { bookingClient } from "@/lib/velexis";
export default async function Extras({ params }: { params: Promise<{ bookingId: string }> }) {
  const { bookingId } = await params;
  const vx = await bookingClient(bookingId);
  const [booking, extras] = await Promise.all([vx.bookings.get({ bookingId }), vx.bookings.getAncillaries({ bookingId })]);
  if (!extras.available) return <p>Extra bags cannot be added online ({extras.notAvailableReason}).</p>;
  return <BagCheckout bookingId={bookingId} version={booking.version} options={extras.options} />;
}
```

```tsx
// BagCheckout (client component): pay first, then add
"use client";
import type { BookingAncillaryOption } from "@velexis/ota-sdk";
import { velexis } from "@/lib/velexis-browser";
import { addBags } from "./actions";

export async function buyBag(bookingId: string, version: number, option: BookingAncillaryOption, travelerId: string) {
  const selections = [{ optionId: option.id, travelerId }];
  const payment = await velexis.bookings.createPayment({ bookingId, selections, expectedTotal: option.price, method: "card", termsAccepted: true,
    returnUrl: `${location.origin}/trips/${bookingId}/extras/return` });
  // mount the provider form with payment.clientSecret; on its brand event: velexis.checkout.updatePayment({ paymentId: payment.id, card })
  // … provider SDK confirms; velexis.checkout.getPayment until "authorized" …
  return addBags(bookingId, version, payment.id, selections, option.price);
}
```

```ts
// actions.ts
"use server";
import { revalidatePath } from "next/cache";
import { isVelexisError, type BookingAncillarySelection, type Money } from "@velexis/ota-sdk";
import { bookingClient } from "@/lib/velexis";

export async function addBags(bookingId: string, version: number, paymentId: string, selections: BookingAncillarySelection[], expectedTotal: Money) {
  try {
    await (await bookingClient(bookingId)).bookings.addAncillaries(
      { bookingId, ifMatch: version, paymentId, selections, expectedTotal },
      { idempotencyKey: `extras-${paymentId}` }, // a same-key retry never PATCHes the order twice
    );
  } catch (e) {
    if (isVelexisError(e, "PRICE_CHANGED")) return { priceChanged: e.details };          // authorisation voided; pay again
    if (isVelexisError(e, "ANCILLARY_NOT_AVAILABLE")) return { notAvailable: e.details }; // authorisation voided
    if (isVelexisError(e, "SUPPLIER_TIMEOUT")) return { checkStatus: true };             // outcome unknown; reload with refresh
    throw e;
  }
  revalidatePath(`/trips/${bookingId}`);
}
```

The bags are added with Flight Order Management PATCH (`additionalServices.chargeableCheckedBags`); the payment is captured only after the airline accepted them, and an EMD is issued when the booking is already ticketed. They appear in `booking.ancillaries` with `source: "post_booking"`.

### 4.5 Cancel (quote → confirm)

```ts
"use server";
import { revalidatePath } from "next/cache";
import { isVelexisError, type Money } from "@velexis/ota-sdk";
import { bookingClient } from "@/lib/velexis";

export async function getQuote(bookingId: string) {
  return (await bookingClient(bookingId)).bookings.quoteCancellation({ bookingId });
}

export async function confirmCancel(bookingId: string, version: number, expectedRefund: Money) {
  try {
    const { cancellation } = await (await bookingClient(bookingId)).bookings.cancel(
      { bookingId, ifMatch: version, reasonCode: "change_of_plans", comment: "Trip postponed", expectedRefund },
      { idempotencyKey: `cancel-${bookingId}-${version}` },
    );
    revalidatePath("/trips");
    return { status: cancellation.status, refund: cancellation.refund, refundStatus: cancellation.refundStatus };
  } catch (e) {
    if (isVelexisError(e, "REFUND_AMOUNT_CHANGED")) return { newRefund: e.details?.newRefund }; // show and confirm again
    if (isVelexisError(e, "SUPPLIER_TIMEOUT")) return { checkStatus: true }; // outcome unknown: bookings.get({ refresh: true }); same-key retries only replay
    throw e;
  }
}
```

`reasonCode` is the typed reason (`change_of_plans`, `illness`, `schedule_change`, `duplicate_booking`, `found_cheaper`, `other`) and `comment` the free text — the same naming as the console, where `reasonCode` is also the code. `booking.cancellation.reasonCode` / `comment` return them.

Quote modes:

| Mode | When | What the customer gets |
|---|---|---|
| `release` | not ticketed yet | full refund minus non-refundable OTA fees; the authorisation is voided if nothing was captured |
| `void` | tickets issued today | tickets voided, full fare refunded (`voidDeadlineAt` shows the cut-off) |
| `refund` | the fare rules allow a refund | refund per the fare rules |
| `request_only` | the OTA must handle it | `cancel` resolves with `cancellation.status = "pending"` (HTTP 202) |
| `not_allowed` | cancellation is not possible | `notAllowedReason` explains why |

### 4.6 Documents and timeline

```ts
// app/trips/[bookingId]/documents/[documentId]/route.ts — keeps tokens server-side
import { bookingClient } from "@/lib/velexis";
export async function GET(_: Request, ctx: { params: Promise<{ bookingId: string; documentId: string }> }) {
  const { bookingId, documentId } = await ctx.params;
  const { url } = await (await bookingClient(bookingId)).bookings.getDocumentDownloadUrl({ bookingId, documentId });
  return Response.redirect(url, 302); // 5-minute signed URL, never cache it
}
```

`bookings.listDocuments` returns e-ticket receipts (after issuance), EMD receipts, the itinerary (regenerated after changes; older versions are `superseded`), invoices and credit notes. A document that is still being generated throws `DOCUMENT_NOT_READY` (409) with `details.retryAfterSeconds`. `bookings.listEvents` returns the customer-visible timeline, newest first, as an async-iterable page.

## 5. Error handling cheat-sheet

| Code (class) | Where | What to do |
|---|---|---|
| `TRAVELER_DATA_INVALID` (ValidationError, 422) | setTravelers, complete, update | map `fieldErrors[].path` to inputs; codes in `TravelerFieldErrorCode` |
| `CONTACT_DATA_INVALID` (ValidationError, 422) | setContacts, complete, update | same |
| `CHECKOUT_INCOMPLETE` (ValidationError, 422) | createPayment, complete | send the user to the step named in `fieldErrors[].path` |
| `ANCILLARY_NOT_AVAILABLE` (ValidationError, 422) | setAncillaries, bookings.createPayment, addAncillaries | remove `selections[details.selectionIndex]` |
| `PRICE_CHANGED` (PriceChangedError, 409) | setAncillaries, createPayment, updatePayment, complete, bookings.createPayment, addAncillaries | show `newPrice`; after createPayment / updatePayment / complete / addAncillaries create a new payment, then try again |
| `SOLD_OUT` (SoldOutError, 409) | setAncillaries, complete | the money is released; go back to search results |
| `PAYMENT_AMOUNT_MISMATCH` (ConflictError, 409) | complete, addAncillaries | the total (or selections) changed after the payment was created: create the payment again |
| `PAYMENT_NOT_UPDATABLE` (ConflictError, 409) | updatePayment | confirmation already started (or the payment is final): create a new payment |
| `PAYMENT_REQUIRED` / `PAYMENT_DECLINED` (PaymentError, 402) | complete, addAncillaries | finish 3-D Secure, or use another card |
| `CHECKOUT_ALREADY_COMPLETED` (ConflictError, 409) | any checkout step | go to `/trips/{details.bookingId}` |
| `CHECKOUT_EXPIRED` / `OFFER_EXPIRED` (ExpiredError, 410) | checkout steps | price again (`flights.price`), open a new checkout |
| `EMAIL_NOT_VERIFIED` (PermissionError, 403) | create, complete | ask the customer to verify the e-mail address |
| `SUPPLIER_TIMEOUT` (SupplierError, 504) | complete, addAncillaries, cancel | outcome unknown: store `details.bookingToken` (guests), poll the booking (`details.bookingId`); same-key retries only replay — **never** repeat with a new idempotency key |
| `TICKETING_FAILED` (SupplierError, 502) | complete (issue at booking) | nothing booked, payment voided; let the customer try again |
| `VERSION_CONFLICT` (409) / `PRECONDITION_FAILED` (412) | update, addAncillaries, cancel | reload with `bookings.get({ refresh: true })`, then retry with the new `version` |
| `BOOKING_NOT_MODIFIABLE` / `BOOKING_ALREADY_CANCELLED` (409) | update, extras, cancel | hide the action (see `allowedActions.reasons`) |
| `REFUND_AMOUNT_CHANGED` (409) | cancel | show `details.newRefund`, ask again |
| `DOCUMENT_NOT_READY` (409) | getDocumentDownloadUrl | retry after `details.retryAfterSeconds` |
| `PAYMENT_PROVIDER_NOT_CONFIGURED` (424) / `PAYMENT_PROVIDER_ERROR` (502) | createPayment, updatePayment, complete, extras | OTA configuration or provider outage; retry with the same idempotency key |
| `NOT_FOUND` (404) | everything | also returned for a resource of the other environment (test key vs live booking) |

The API documents these codes per area in its error responses (`CheckoutConflict`, `CheckoutUnprocessable`, `CheckoutForbidden`, `PaymentFailedDependency`, `PaymentProviderError`, `CheckoutSupplierTimeout`, `BookingConflict`, `BookingUnprocessable`, `BookingSupplierTimeout`, `DocumentConflict`), with the `details` of each code.

### Where the Flight Create Orders fields come from

| Amadeus field | Source |
|---|---|
| `flightOffers` | the checkout's priced offer (net Amadeus offers, ancillaries in `additionalServices`) |
| `travelers` | `checkout.setTravelers` (`id` = `travelerId`, decrypted full document numbers) |
| `contacts` | `checkout.setContacts`, plus the OTA agency contact (storefront setting) |
| `remarks.general` | `checkout.setRemarks`, plus the storefront's back-office remarks |
| `remarks.airline` | storefront settings |
| `ticketingAgreement` | `CONFIRM` when paid; for `pay_later` `DELAY_TO_CANCEL` (or `DELAY_TO_QUEUE`) with a `delay` such as `"2D"` that Velexis derives from the storefront pay-later policy and the offer's `lastTicketingDate`. `dateTime` is output-only in Amadeus and is never sent; it is read back to compute `ticketing.deadlineAt` |
| `automatedProcess` | storefront settings (queue number/category, officeId, delay, text) |
| `queuingOfficeId`, `ownerOfficeId` | the tenant's Amadeus connection (`platform.supplier_connections`) |
| `formOfPayments` (OTA-merchant model) | `other.method` (ACCOUNT / CASH / NONREFUNDABLE) or `b2bWallet` |
| `formOfPayments` (card pass-through) | `creditCard`, forwarded by the payment provider, with `paymentOperationContext.threeDomainSecure` taken from the provider's 3-D Secure result |
| `commissions`, `formOfIdentifications` | storefront settings / airline rules |
| query `issue` | `ticketing_policy = issue_at_booking`, or the offer's `instantTicketingRequired` |

### Storefront settings that change behaviour

`guest_checkout_enabled`, `require_email_verification`, `ticketing_policy` (`issue_at_booking` | `issue_after_payment` | `manual_review`), `payment_timing` (`authorize_before_booking` | `capture_before_booking` | `pay_later`) and the pay-later hold, `accepted_card_brands`, `require_3ds`, `checkout_ttl_minutes`, `features.ancillaries` (also gates extra bags after booking), and the self-service cancellation switch. They are visible to the storefront through `storefront.get` (B1) and `checkout.ticketing`.
