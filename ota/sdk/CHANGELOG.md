# Changelog of `@velexis/ota-sdk`

Every change that a consumer of the SDK can notice is recorded here by hand, newest first ([OADR-0016](../docs/adr/0016-sdk-packaging-and-type-contract.md) point 8). The SDK follows [semantic versioning](https://semver.org/): a change that the contract test would reject is a major version, new methods and options are minor, fixes are patches. Versions `0.x` live only in the workspace (`workspace:*` in the storefront and the OTA admin); `1.0.0` is the first npm release (M6). `VERSION` in `src/version.js` always equals `version` in `package.json` (a unit test fails otherwise), so a release changes both and adds its section here.

A method that will be removed is marked `@deprecated` in its JSDoc for at least one minor release first, and the deprecation is listed here.

## 0.1.0 (unreleased, workspace only)

### Added

- The bundles (SDK-007): `pnpm --filter @velexis/ota-sdk build` writes `dist/velexis-sdk.mjs` (ESM) and `dist/velexis-sdk.iife.js` (IIFE defining `window.Velexis`), both ES2022, minified, self-contained and with linked source maps, and the declarations in `dist/types/`, then fails when the ESM bundle exceeds 25 KB min+gzip (11.3 KB now). `package.json` `exports` `"."` → `types`, `development` (`src/index.js`, for Vite's dev server and Vitest), `import` (the ESM bundle) and `default` (the same bundle, so CommonJS code can `require()` it on Node 22), and `"./iife"`; `files` lists `dist`, `src`, `README.md` and `CHANGELOG.md`. Importing either bundle performs no request and changes no global except the IIFE's `window.Velexis`.
- The M2 namespaces (SDK-005): `storefront` (`get`, and `resolve`, deferred: `ServerError` `NOT_IMPLEMENTED`), `reference` (`locations.search`, `airports.get`, `airlines.list`, `airlines.get`, `countries.list`, `currencies.list`, the lists as `Page`s) and `flights` (`search`, `getSearch`, `listResults` with the page's facets, `getOffer`, `upsell`, `availability`, deferred, `price`, `getPricedOffer`, `getAncillaries`, `getFareRules`), each named by its `x-sdk-method` and sent through the route table (60 s for `search`, `upsell` and `price`); `flights.*` send `cache: "no-store"` unless the call sets `cache` or `next`; `storefront.get({ locale })` as a shortcut for `options.locale`. The public modules `identity.js` (storefront and reference part) and `flights.js` with the typedefs of their contract files and the factories `createStorefrontApi`, `createReferenceApi` and `createFlightsApi`.
- The session modes (SDK-004): cookie mode (`session: "cookie"`: same-origin `fetch` with cookies, `/api` by default, keys, tokens and credential headers refused with a `TypeError`, `X-CSRF-Token` from `__Host-vx_csrf` with one `GET /v1/storefront` when it is missing or refused, refresh through `POST /v1/auth/refresh` with an empty body), token mode (`credentials: "omit"`) and server mode (`secretKey` refused in a browser page, `environment` → `X-Velexis-Environment` on console operations); the automatic refresh on `401 TOKEN_EXPIRED` with one refresh for concurrent calls, `sessionKind: "staff"` through `console.auth.refresh` with `onStaffSessionRefreshed`, `onSessionExpired` when the refresh is refused, and the rotated tokens kept by the client.
- The request core (SDK-003): `createVelexisClient` with option validation and the contract's defaults, `withOptions` and the `request` escape hatch; headers (`Accept-Language`, `X-Currency`, `X-Velexis-Host`, `X-Velexis-End-User-*`, the API key and tokens, caller headers), one `Idempotency-Key` per call reused across its retries, timeouts linked to `options.signal`, retries with back-off and `Retry-After`, the `onResponse` hook; the contract's error classes (`VelexisError` … `ServerError`) with `isVelexisError` and a `toJSON()` without keys or tokens; `Page<T>` with `next()` and `for await` across pages. The namespaces follow from SDK-005.
- The package scaffold (SDK-001): an ES module package with `"sideEffects": false` and no runtime dependencies; `VERSION`, the only export so far; the base type aliases `Schemas`, `Paths` and `Operations` from `@velexis/api-types` (JSDoc types only); `tsc --checkJs` with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and no Node globals; declaration-only emit to `dist/types/`; Vitest with a fake `fetch` for the unit tests.
